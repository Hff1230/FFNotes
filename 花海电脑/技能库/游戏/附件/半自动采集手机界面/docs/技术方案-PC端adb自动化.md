**■ 倩女幽魂手游 · PC 端 adb 自动化 技术方案**

> 版本 v1.0 / 2026-09-18
> 原则：**每一条结论都附实测数据与可复跑脚本**；未验证的项明确标注「未验证」，不写推测当结论。

---

**▍ 0. 方案摘要**

用**电脑通过 adb 驱动真机**，在 PC 侧完成「截图 → 界面识别 → 决策 → 拟人注入 → 结果验证」闭环。
识别全程**本地零 token**（比色 + 本地 OCR），不调用任何 AI 视觉。

核心技术判断：

1. **识别不用大漠，用 cv2 归一化互相关 + 本地 OCR** —— 实测准确率 100% vs 大漠式 20%（同任务同扰动）。
2. **不用手机端脚本框架**（AutoX.js / 按键精灵手机版）—— 那会额外暴露「无障碍服务」和「应用包名扫描」两条检测面。
3. **adb 注入通道的检测特征换不掉** —— 这是本方案的**唯一硬伤**，见 §5，必须知情。

**▍ 3. 分层技术选型与实测依据**

**· 3.1 采集层**

| 项 | 选型 | 依据 |
|---|---|---|
| 截图 | `adb exec-out screencap -p` | `adb shell screencap` 通道会 LF→CRLF 损坏 PNG；exec-out 二进制安全 |
| 坐标空间 | **截图像素 = 点击坐标（1:1）** | 实测横屏 `cur=1600x720`、PNG IHDR 1600×720、uiautomator `rotation=1` 三者同空间 |
| 解析顺序 | `SurfaceOrientation`（1/3=横屏）+ `wm size` 旋转后尺寸 | 华为机 `wm size` 给 `Physical 1080x2400` + `Override 720x1600`，按 Physical 缩放会整体偏移 |
| UI 节点 | **不用** uiautomator | 实测该游戏 dump 只有 6 个 node、text 全空（Unity 自绘） |

**· 3.2 识别层（核心）——三层级联，全程零 token**

| 层 | 手段 | 耗时 | 作用 |
|---|---|---|---|
| L1 | 多点比色指纹（纯 numpy，16 采样点，tol=6） | ~2ms | 候选预筛 |
| L2 | **固定 ROI 的 OCR**（RapidOCR `use_det=False`） | ~20ms | **决策层** |
| L3 | 全屏 OCR（`det=True`） | ~1.4s | 兜底 + 自校准 |

**为什么 OCR 是决策层而不是比色**：比色是「相似度」不是「语义」。实测旧版把「设置」误判成「背包」就是这么来的 —— 配色相近的界面互相混淆。

**为什么 L2 用固定 ROI**：建图期用全屏 OCR 拿到关键词的精确框，外扩 8px 固化成 ROI。运行时只读这块小图 → **20ms 而不是 1500ms**。

**为什么需要 L3**：固定 ROI 快但脆，游戏 UI 改版/换分辨率会失效。L3 是全屏搜索，等价于大漠 `FindStr` 的灵活性。

**· 3.3 工具选型：为什么不用大漠插件（实测决定）**

**·· 3.3.1 本机大漠的真实状态**

| 项 | 事实 |
|---|---|
| 手上的东西 | `大漠接口说明 v3.1233`（CHM，2017-10-26 编译，收录 54 个命令） |
| 缺的东西 | **`dm.dll` 本体** —— D 盘全盘（深度 5）搜 `dm.dll` 零命中 |
| 注册表 | `HKCR\dm.dmsoft` 是**孤儿**：指向的 CLSID `{26037A0E-…}` 在注册表里不存在 |
| Python | 本机三个解释器**全是 64 位**，无法加载 32 位 COM |

**·· 3.3.2 算法对比实验（`scripts/bench_tolerance.py`，180 次判定 / 12 种真实扰动）**

扰动集：亮度±15%、弹窗变暗遮罩×0.6、暖/冷色温、位移 2/5px、JPEG q50、缩放 95%/105%、噪声 σ=8。

| 算法 | 判别准确率 | 裕度（正确最低 − 错误最高） |
|---|---|---|
| 多点比色（拿文字当模板） | 无效（平坦点 0 个） | — |
| **cv2 `TM_CCOEFF_NORMED`** | **180/180 = 100%** | **+0.797 ✅** |
| 大漠式 FindPic（逐通道绝对差+比例） | 36/180 = 20% | **−0.287 ❌ 区间重叠** |

大漠式扫 delta 也救不回来：`delta=32 → 20.6%`、`64 → 13.9%`、`96 → 15.0%`。
**正确最低分 0.478 < 错误最高分 0.764**，单阈值分不开；且大漠默认 `sim=0.9` 比正确最低分还高，**默认参数下判不出任何结果**。

**原因是结构性的**：归一化互相关减均值除标准差，对线性光照变化**天生免疫**；绝对差法不免疫，只能放宽容差，一放宽纯色区就虚高。

**·· 3.3.3 「更安全的版本」这个问题的答案**

| 维度 | 大漠版本的影响 |
|---|---|
| 手机端反作弊检测 | ❌ **完全无关**（PC 侧进程，游戏看不到） |
| 下载来源安全 | ⚠️ **这里才是真风险**：网上「破解版/去广告版 dm.dll」是木马重灾区（COM 组件可拿任意权限）；正版免费版只有 2011 年的 3.1233（新系统兼容差、有广告），新版要买码 |
| 「更好用」 | 唯一真实优势是**全屏搜索不受固定坐标约束** → 已由 L3 补齐 |

**结论：不引入大漠。** 换任何版本都买不到容错收益，且引入闭源 COM 组件本身是新的风险面。

**· 3.4 注入层**

| 项 | 选型 | 说明 |
|---|---|---|
| 原语 | `input swipe x y x y <dur>`（零距离 swipe） | `input tap` 的 DOWN/UP 时间戳完全重合、坐标零抖动、间隔恒定 —— 反外挂最易识别的机器特征 |
| 坐标抖动 | ±5~12px | 避免同像素重复点击 |
| 间隔 | **对数正态分布**（中位 ~0.55s，12% 概率追加 1.2~3.5s「走神」停顿） | 恒定节拍最像脚本 |
| 滑动 | 拆 4 段 + 轻微侧向弧度 + 分段变速 | 不描完美直线 |

**· 3.5 验证层**

**判据（唯一可信）：`截图A → 动作 → 截图B → 逐像素比对`**

- 判定：**变化>40 的像素占比 > 3%**（基准来自实测：HUD 本底动效 0.97%，有效点击 3.70%~10.73%）
- ⚠️ **禁止用「焦点窗口是否变化」判断注入是否生效**（已踩，假阴性）：华为手势导航会把某些 fling 交给系统，焦点不变但事件确实到达
- ⚠️ 判定必须**扣掉该界面的本底动效**，否则启动页水面/花瓣的 3.7% 变化会被误判成点击生效

**· 3.6 护栏层（硬编码，流程绕不过）**

```
点前三重校验：
  ① ALLOWED 白名单    —— 动作名不在白名单直接拒绝
  ② FORBIDDEN 黑名单  —— 商城/购买/充值/月卡/回收/放弃任务/离开队伍… 永不点击
  ③ is_danger 半径检查 —— 坐标落在危险区 45px 内直接拦截
点后双重验证：
  ④ 像素变化率 > 3%
  ⑤ 二次识别 == 期望界面
```

已登记 **7 条危险区**，含 `dialog_exit` 的「确定」(947,432)——点了会真的退出游戏。

**▍ 5. 检测面分析与风险（必须知情）**

**· 5.1 三条检测面对照**

| 检测面 | 本方案状态 | 换大漠能改善？ | 换手机端框架会怎样 |
|---|---|---|---|
| 游戏扫已安装应用（找按键精灵/AutoX/GG） | ✅ **手机零安装** | ❌ 无关 | ❌ 反而中招 |
| 无障碍服务列表（`getEnabledAccessibilityServiceList()` 直接抓包名） | ✅ **未开无障碍** | ❌ 无关 | ❌ 反而中招 |
| **adb 注入通道特征** | ❌ **换不掉** | ❌ 无关 | ✅ 能规避，但换来上面两条 |

**· 5.2 adb 通道的固有特征（硬伤）**

游戏**不需要任何权限**就能读到：

```java
event.getSource()    // = SOURCE_UNKNOWN（不是 SOURCE_TOUCHSCREEN）
event.getDeviceId()  // = 0（不是真实触摸屏 id，也无对应 InputDevice 实体）
event.getPressure()  // = 1.0 固定
// 且无历史采样点
```

这是**通道固有**的，与用大漠/openCV/任何视觉工具都无关 —— 因为视觉工具只在 PC 侧读图，注入仍走 adb。

**· 5.3 各注入通道隐蔽性排序**

| 通道 | 隐蔽性 | 本机可用性 |
|---|---|---|
| PC adb `input` | **最低** | ✅ 零改装 |
| 手机端无障碍 `dispatchGesture` | 中 | 需装框架（额外暴露两条检测面） |
| root + uinput 注入 | 高 | ❌ 华为 2018 年后不能解 bootloader |
| 硬件 HID（OTG 模拟触摸屏） | **最高**（只剩行为分析） | 需额外硬件 |

**· 5.4 风险如实说明**

- 倩女幽魂官方《玩家守则》把「**自动打怪、自动练级、自动吃药、自动完成任务**」明列为第三方软件
- 处罚阶梯：强制离线 → 暂时隔离 → 永久隔离 → 禁止登录 → 冻结物品 → **封停账号** → 法律责任
- 网易有 NACE 游戏安全团队 + 易盾反外挂 SDK
- **行为风控权重 > 通道检测**：通道再隐蔽，恒定节奏/固定坐标/24 小时在线一样会被盯上
- **封号风险由账号承担**。本方案在拟人化和行为节奏上做了工程控制，但不承诺免检。

**· 5.5 已识别但**不建议走**的方向**

⚠️ `D:\leidian` 有雷电模拟器。走「模拟器 + PC 大漠后台绑定」路线会**额外引入模拟器检测面**（`ro.kernel.qemu`、传感器数量、CPU 特征），比真机+adb 更差。

| **P3** | 单流程实跑：接货运任务（低风险白名单动作） | 端到端截图证据链 | P2 |
| **P4** | 补齐日常链路界面（采集 + 建图，复用现有工具链） | 图谱扩充 | P3 |
| **P5** | 长时挂机 + 异常恢复（退出弹窗 / 未知界面停手 / 断线） | 稳定性报告 | P4 |

**▍ 9. 遗留问题与已知坑（供后续接手者）**

1. **比色选点不能用「11×11 局部平坦约束」** —— 实测在游戏 HUD 场景图上满足率 **0.000%**（flat p50=44.6）。必须用 Fisher 判别准则（between/within）。
2. **`TM_CCOEFF_NORMED` 有纯色虚高陷阱** —— 搜索区接近纯色时相关系数虚高（实测别的界面模板在纯色区拿到 0.998）。必须加信息量门限：匹配处局部灰度 std < 10 即作废。
3. **`cv2.imread` 读不了中文路径** → 用 `np.frombuffer(open(p,'rb').read())` + `cv2.imdecode`。
4. **界面分组必须用 OCR 文本核对** —— `hud_00_a/b/01/02` 文件名像 HUD，OCR 显示是「九久同心」活动页；分组一错后续选点全废。
5. **BACK 键不关闭上层面板**，而是弹「是否要退出游戏」。`BACK → 取消` 是原地打转，关闭面板只能找该面板自己的 ✕。
6. **华为 USB 会掉成 `offline`**（不是 `unauthorized`）—— USB 连接方式自动回落「仅充电」。很多线只有充电芯没有数据芯。
7. **`adb kill-server` 字样会触发本机 hardline 阻断**；多行长命令会被判超长 payload 整条拒掉——拆短命令。
