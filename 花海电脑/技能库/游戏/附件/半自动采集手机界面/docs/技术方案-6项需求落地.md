**·· ✅ 4.5.1 时间冲突与优先级（用户已拍板）**

**用户规则（2026-09-18 原话）**：

> **一条龙期间不中断，不管其他活动。**

即 **一条龙 = 独占锁（exclusive lock）**：一旦进入就抢占一切，直到完成。

三项限时活动的时间窗本就互相重叠：

| 时段 | 守财奴 | 帮会大盗 | 采薇 |
|---|---|---|---|
| 每天 **12:00–19:30 的每个整点** | ✅（整点 / 15分 / 30分） | ✅（每个整点） | 视星期 |
| 每周一 / 三 / 四 的 8 个时段 | ✅ | ✅（若落在 12:00–19:30 内） | ✅ |

**最终优先级**：

| 优先级 | 任务 | 说明 |
|---|---|---|
| **P0 独占** | **一条龙** | 进行期间**屏蔽所有其他调度**；守财/采薇/帮会大盗的刷新点一律跳过 |
| P1 | 守财奴 | 窗口 = 秒级（全服抢） |
| P2 | 采薇 | 窗口 = 分钟级（全服抢） |

| P4 | （原）宝图任务 | ❌ 已取消 |

**实现：调度器加独占锁**

```python
class Scheduler:
    def __init__(self):
        self.exclusive = None      ＃ 独占任务（一条龙）进行中则非 None
    def start(self, task):         ＃ 进入独占流程
        self.exclusive = task
    def finish(self, task):        ＃ 完成 / 失败 / 超时后释放
        self.exclusive = None
    def due_now(self):
        if self.exclusive:         ＃ ★ 独占期间一律不调度其他活动
            return []
        return [t for t in self.table if self._due(t)]
```

**独占锁必须有超时保护**：一条龙若卡死（如副本出不去、角色卡图），不能永久锁住调度 →
`max_duration = 120 分钟`，超时强制释放 + 存证 + 通知你。否则一次卡死会让后面所有活动全部错过。

**·· ✅ 4.5.2 错峰逻辑：用户决定「不要」**

一条龙耗时通常很长（多小时），期间会**连续错过**守财奴的每个整点 / 15分 / 30分刷新：

- 例：**13:50 开始一条龙** → 14:00 / 14:15 / 14:30 / 15:00 … 全部错过

**建议（不违反你的规则）**：调度器在**决定开始**一条龙**之前**，检查未来 15 分钟内是否有 P1/P2 活动：

```
若要开始一条龙，但 15 分钟内守财/采薇要刷
  → 先等那轮活动做完，再进一条龙   ← 这是「错峰」，不是「中断」
```

**用户决策（2026-09-18）**：**不考虑错峰** —— 一条龙一般 **1 小时**就结束，错过一两轮守财的代价可接受。

> 配套：独占锁超时仍设 **120 分钟**（1h 正常 + 1h 余量），超时强制释放 + 存证 + 通知。

**· 4.6 技术难点：野外目标识别（最大风险）**

这两个活动都要在**野外场景**里找到目标，而目标是**场景内的游戏物体**，不是 UI 元素：

| 目标 | 特征 | 识别难度 |
|---|---|---|
| 守财奴 | 野外 BOSS 模型 + 右上角「守」**字**提示 | **中**（「守」字可用 OCR/比色，怪物模型可模板匹配） |
| 薇草 | 场景里的草/小鹿（"薇草被成精的鹿儿马儿抢了去"） | **高**（无自动寻路，纯视觉搜索） |

**对策**：
1. **优先用游戏自带寻路**：守财奴有「守」字提示，若能点击提示自动寻路则最简单（待真机确认）
2. **模板匹配 + 多尺度**：野外光照/地形变化大 → 需要多样本模板（我方已有 `TM_CCOEFF_NORMED` + 信息量门限，实测最强）
3. **缩小搜索范围**：只在刷新点附近的小地图区域内搜，不做全屏扫描
4. **兜底：交给用户**。找不到就停手报警，不瞎跑

**· 4.7 ⚠️ 可行性风险（必须知情）**

1. **抢不到是常态**。玩家攻略原文：「守财想做就做**基本抢不到**太少了」。这两个是**限时+限量+全服竞争**的野外活动，脚本能做的是「准时蹲点 + 尽力找 + 找到就点」，**但成功与否取决于服务器竞争**，脚本保证不了。
2. **采薇无自动寻路** → 找薇草是纯视觉搜索，是全方案里**最难的一项**。
3. **抢怪影响行为特征**：为了抢怪，动作会变快变急（与"拟人"冲突）——这是**内在矛盾**，需要你权衡：
   - 拟人优先 → 抢到的概率更低
   - 抢怪优先 → 行为更像脚本，风控风险上升
4. **刷怪瞬间会弹签到页**（攻略提到）：关页面的时候身边的守财可能被别人抢了 → **§1 弹窗处理必须极快**，这是个真实的性能要求。

**· 4.8 仍需你确认**

| # | 问题 | 为什么 |
|---|---|---|
| 1 | 你是**队长**还是**队员**？ | 队长要负责找目标并点击；队员只需跟随 + 挂机。**这决定脚本要做多少事** |
| 2 | 刷新后你是**自己找**还是**等别人喊位置**？ | 决定要不要做自动寻路 / 视觉搜索 |
| 3 | 这两个活动的**入口**：地图传送？活动面板？NPC？ | 决定第一个动作 |
| 4 | 是否需要**自动判断今天还有几次额度**（守财每日上限 10 次）？ | 决定要不要读次数显示 |

**或者**：你把「刷出守财/薇草时的游戏画面」截 2~3 张给我（含右上角「守」字那屏），我用现有工具链（`ocr_all.py` + `build_map_real.py`）把识别方案定下来。

**·· ⚠️ 4.10 运行模式：24H（用户已决）**

**实际运行模型（用户澄清 2026-09-18）**：

> **24H 只是常驻挂着；只在活动窗口内操作，空闲时段空等、完全不操作。实际操作时长不会太久。**

这**大幅改变风险性质** —— 与"24h 持续操作"不是一回事：

| 因素 | 影响 |
|---|---|
| 空闲时段无任何操作 | = 游戏里常见的"挂机"，本身不异常 |
| 操作窗口集中在 **13:00 – 00:30** | 恰是活跃玩家在线区间 → **与人类作息吻合** |
| 实际累计操作时长短 | 只有刷新点前后的窗口，不是全天连续动作 |

**残余风险（如实保留）**：

| 项 | 说明 | 建议 |
|---|---|---|
| **准点响应** | 每次刷新都分秒不差地开始动作 = 机器特征 | 加 **±3~15 秒随机偏移**（不追求准点反而更自然，抢怪影响极小） |
| **00:30 最后一波** | 凌晨时段活跃玩家少 | 该波可考虑跳过（由你定） |

> 采用与否由你定；不采用也照 24H 跑，此处仅如实记录。

**▍ 5. 需求 6：发现非法检测或制裁 → 立刻结束游戏 ⚠️**

**· 5.1 .q 脚本里没有这个（只有 `是否断线重连`）**

需**自建看门狗**。这是本方案**风险最高**的一项，因为它会主动杀游戏进程。

**· 5.2 检测手段（分级）**

| 级别 | 检测项 | 手段 | 置信度 |
|---|---|---|---|
| **A 高** | 游戏进程消失 | `adb shell pidof com.netease.l10` 返回空 | 确定 |
| **A 高** | 被踢回登录/启动页 | 识别为 `panel_serverlist` / 启动页 | 确定 |
| **A 高** | 反作弊文字弹窗 | OCR 命中黑词：`第三方`/`违规`/`作弊`/`封停`/`隔离`/`冻结`/`制裁`/`异常` | 高 |
| **B 中** | 出现图谱外的**未知全屏界面** | 识别返回 `None` 且全屏变化 >50% | 中 |
| **B 中** | 真人/滑块验证 | OCR 命中 `验证`/`滑动`/`拖动` + 界面非已知 | 中 |
| **C 低** | 行为风控预警 | 无可靠本地信号 | — |

**· 5.3 应对动作（分级可配）**

```yaml
＃ config/watchdog.yaml
actions:
  A: {kill_app: true,  stop_script: true, save_evidence: true, notify: true}   ＃ 立刻结束游戏
  B: {kill_app: false, stop_script: true, save_evidence: true, notify: true}   ＃ 先停手存证，等你确认
  C: {kill_app: false, stop_script: false, log: true}
```

**为什么 B 级默认不直接杀游戏**：「未知界面」也可能只是**没采集过的新活动面板**。误判杀游戏会打断你正在进行的游戏 → B 级先停手+存证+通知，由你决定。
若你要求「宁可误杀也不放过」，B 级也能配成 `kill_app: true`。

**· 5.4 执行细节**

```bash
adb shell am force-stop com.netease.l10        ＃ 结束游戏

＃ 存证（硬要求，用于事后判断是不是误判）
evidence\watchdog\<时间戳>\ {触发帧截图, 识别结果JSON, logcat 摘要, 前后各 3 帧}
```

**存证是硬要求**：没有存证就无法复盘「到底真被检测还是脚本误判」。

**· 5.5 定位澄清（重要）**

| | |
|---|---|
| ✅ **能做的** | **事后止损**：检测发生时尽快收手（杀游戏 + 停脚本 + 存证） |
| ❌ **做不到的** | **降低被检测的概率**。`getSource()=SOURCE_UNKNOWN` 是 adb 通道固有特征，换不掉 |

**所以需求 6 是「止损机制」不是「防检测机制」。** 降低概率只能靠行为拟人（已有）+ 运行时长控制（**需你决策，24h 挂机风险最高**）。
