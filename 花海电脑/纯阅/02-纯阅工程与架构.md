## 2. 数据与文件格式

**数据表（DBHelper.ets）**

```sql
books(id, title, author, format, path, cover, size, addTime, lastReadTime,
      progress REAL, offset INTEGER, chapterIndex INTEGER, chapterTitle TEXT, encoding TEXT)
bookmarks(id, bookId, offset, chapterIndex, chapterTitle, excerpt, createTime)
settings(skey PRIMARY KEY, svalue)          -- pageMode / fontSize / lineHeight / 段间距 / 主题 / tts* 等
folders(id, name, createTime, sortOrder)
book_sources(id, name, url, groupName, enabled, searchUrl, searchMethod, …)   -- 仅自用版
```

**位置三件套**：`offset`（全书字符偏移，最精确）+ `chapterTitle`（章节名，正文重排后仍可信）+ `progress`（百分比，兜底）。恢复优先级见 03-A-2。

**随书 sidecar（沙箱，与书同目录）**

| 文件 | 内容 | 状态 |
|---|---|---|
| `<书>.idx` | 章节索引：`文件字节数 + 正文字符数`（校验用）＋ **每章字节区间**（供按章窗口读）＋ **块索引表**（`章号 + 章内块偏移 + 累计序号`，供位置映射） | ⚠️ 现只有前两项；后两项待实施（FIX-002 / 优化 P0-1，**格式一次定好**） |
| `<书>.report.json` | 整理报告：规则版本、扫描/保留行数、各类删除数、**被删行样本**、存疑保留、缺章列表、耗时 | ⬜ 待实施 |
| `<书>.raw` | **抓取书专用**：未整理的原始正文（按章存，可压缩）——"落盘即整理"的安全垫 | ⬜ 待实施 |

⚠️ **`.idx` 一次定格式**：内存窗口化（按章读）与位置映射都依赖它，两件事必须合并设计，别先做一个不能窗口化的索引。

### 已测基线（2026-10-14 11:13，**模拟器** x86／HarmonyOS 7.0.0.107，测试书 `剑来` 39.8MB / 1385 章）

> ⚠️ **口径**：模拟器绝对值不能等于真机（真机 21.9MB 书约 2~3s 开）；**它只用于"同一目标改前改后"对比**。真机复测请在 Pura 70 Pro 上重跑一遍（hdc 无线调试）。
> 触发流程（可复现）：`hdc file send 'C:\...\剑来.txt' /storage/media/100/local/files/Docs/jianlai.txt` → App 内「导入」→ 点书。

| 指标 | 实测基线 | 备注 |
|---|---|---|
| 打开书到正文（38MB，首次重扫建索引） | **≈9.1s**（11:13:12.19 首帧 → 11:13:21.32 `loaded …(本次重扫)`） | 首帧出现时 `chars=0`，是空白态 |
| 打开书到正文（同书，**用索引缓存**） | **≈7.9s**（11:13:37.80 点击 → 11:13:45.75 `loaded …(用索引缓存)`） | **有缓存也慢**，说明瓶颈不在索引构建 |
| 内存 PSS（打开 38MB 书后） | **152~166MB**，swap **≈38MB** | `hidumper --mem` 两次：156,090KB / 169,607KB |
| 正文常驻 | 日志 `loaded 13825805 chars` ⇒ 整本 1380 万字符常驻 | 与"按章窗口读"目标（≤40MB）直接冲突 |
| 包体（HAP） | **1,883,398 B** | 本机 `entry-default-signed.hap` |
| 滚动帧率 | 待 DevEco Profiler | 模拟器帧率意义有限，真机测 |
| 功耗/温度 | 不测（模拟器无意义） | 真机抓取/听书场景再量 |

**基线结论**：① 首屏与内存两条都差得远，**且"有索引缓存"也救不了首屏** ⇒ 性能批次第一刀应切"按章窗口读 + 首屏先出当前章"；② 内存 152~166MB 与真机 148MB 同量级，说明是结构性问题（不是真机特有）。

### 窗口读实测（2026-10-14 11:26~11:30，同一台模拟器 + 同一本书，改前/改后对比）

| 指标 | 改前（基线） | **改后（窗口读）** | 提升 |
|---|---|---|---|
| 首屏（点击 → 正文上屏） | 7.9s | **0.5s**（冷启动约 1.2s） | **≈6~14×** |
| 内存 PSS（打开 38MB 书） | 152~166MB（swap ≈38MB） | **70MB** | **↓55%** |
| 日志证据 | `loaded 13825805 chars / 1385 chapters (…)`（整本解码） | `窗口读：openByIndex 命中，1385 章 / 13825805 字（未解码整本）` → `窗口读：ch 0..8 共 38377 字（字节 0 起）` | — |

**实现要点（读代码前先看这段）**
1. 索引升 **v2**：章节表之外多存**分片表**（`b` 字节起点 / `c` 字符起点 / `n` 本片字符数 / `u` 是否不安全）+ `enc` + `mt`（mtime）；校验 `size`＋`mtime`。
2. `openByIndex()`：只读索引（毫秒级）拿章节表 + 全书字符数 → **不整本解码**；命中老 v1 索引时会**顺手升级成 v2**。
3. `readWindow(path, idx, fromCh, toCh)`：seek 到对应分片 → 解码 → 按字符坐标切片 → 返回这几章文本；**自校验**：解出的字符数必须等于分片表 `n` 之和，不等就**退一片重读**（分片边界可能落在多字节汉字中间），退到第 0 片必然对齐 ⇒ 错位不可能蒙过去。
4. `Reader`：`ensureWindow(章)`（当前章 ±8）＋ `sliceGlobal(全书区间)` ＋ `excerptNear()`；`this.text` 在窗口模式下保持空串，全书长度改用 `textLen`。
5. **一键回退**：设置 `windowedText=0` ⇒ 原样走整本 `load()`；**带书源的书**（要 `appendTail` 增量补章）与 epub 也走整本。
6. 反向依赖：`.idx` 的**字节区间**（内存窗口化第二步）与**块索引表**（FIX-002）都要在这个 v2 格式上继续加字段 —— 一次定好。

## 5.5 滚动模式「按章切换」工程落点（2026-10-14 落地，01 §2.1 规格）

| 落点 | 做法 | 为什么只能这样 |
|---|---|---|
| 窗口范围 | `windowRange()` **恒返回 `[当前章, 当前章]`**（老的多章连排逻辑留作 `windowRangeMulti()` 备退） | 规格要求「章节不同时出现在屏幕上」；且多章连排下 `currentOffset()` 会被夹进当前章区间 → 页码恒为「本章第 1 页」 |
| 邻居上下文 | `buildWindow()` 里 `head/tail` 恒 `false`（`ctx=n`） | 否则章末会露出下一章开头，章首/章末按钮的可见位置也跟着乱 |
| 自动换章 | `maybeShiftWindow()` 在滚动模式**直接 return** | 原来「滚过半屏就换窗口」＝用户看到的「直接滚到第四章」 |
| 换章入口 | 只有三条：章首「上一章」、章末「下一章」按钮、目录/书签跳转、听书自动推进 | 滚动本身不许跨章；一章滚到底由 `EdgeEffect.Spring` 自然停住 |
| 切章位置 | `gotoChapter(i,false)`＝新章开头；`gotoChapter(i,true)`＝上一章**末尾**（`pendingRestoreRatio = windowRatioOf(ch.end-1)`） | 规格：点「上一章」要接上文，不是回到上一章开头 |
| 按钮显隐 | 章首「上一章」`if (this.curIndex > 0)`；章末「下一章」`if (this.curIndex < 章数-1)` | 首章/末章不显示；短章不足一屏时两个同时可见 |
| 页码胶囊 | 切章后**延后 300ms 强制** `updatePageLabel(true)` | 切章瞬间 `pageStarts`/滚动位置都还没落定，当场算出来的是上一章残留 |
| 切章定位 | `settleChapterScroll(toEnd)`：300ms 后自己 `scrollTo`（章首→0 / 章末→`maxScroll`）+ 刷页码 + 刷高亮 | **`LazyForEach` 数据源变化不会重置 List 滚动偏移**，会沿用上一章偏移 ⇒ 停在半中腰；只靠落位纠不回来（落位会放弃） |

⚠️ 单章视图让窗口从 ≈20 章缩到 1 章（例：`max` 143094 → 12279），**章内自校准仍是唯一的位置来源**；位置跳动的判据/修法见 `docs/fix/scroll_progress_jump/`。
