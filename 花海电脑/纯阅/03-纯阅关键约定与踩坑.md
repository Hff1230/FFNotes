# 纯阅 · 关键约定与踩坑

> 这里每一条都是**用真机事故换来的**。改相关代码前先读，别重新发明。

## A. 红线与总口径

1. **任何情况下不许损坏阅读进度**——写库前必须自检，宁可这一次不写：位置三件套（`offset` + `chapterTitle` + `progress`）里任何一个对不上，都按"伪值"处理。
2. **位置锚（三态回退）**：恢复位置时
   ① 章号能从偏移推出、且与记下的章节名一致 → 用偏移（最精确）；
   ② 两者冲突（正文被重排/续抓/换源）→ **以章节名为准**；
   ③ 偏移越界 → 章节名 → 「进度 × 源目录总章数」→ 最后退到记下的章号。
3. **进度的分母用「源目录总章数」**（`srcTotal`），不用"已抓章数"——否则补章后进度会往回掉。
4. **保存前自检三条**（伪值一律不覆盖库里的好位置）：
   - 偏移越出当前章区间 → 丢弃
   - 布局还没完成（`maxScroll=0`）且用户没滚动，却跳了 1 章以上 → 丢弃
   - 章号只差 0~1 章、用户没滚动，进度却突变 >25 点 → 丢弃
   ⚠️ **已知缺口**：只拦「跳 >1 章」，跳 **1** 章的伪位置会漏过去（实测：打开时在第 1 章 off=230，3 秒后自己变成第 2 章 off=4013＝第 2 章开头，退出后就被存住了）。修法见 [[04-纯阅待办与验收]]。
5. **落库时机**：`aboutToDisappear`（退出阅读页）**不够**——用户直接回桌面/切走不会触发。必须三条一起：
   ① `EntryAbility.onBackground` 打 `AppStorage.setOrCreate('appBgTick', Date.now())` 心跳 → 阅读页收到立刻写库；
   ② 阅读中滚动/翻页停稳 ≥8 秒节流落库；
   ③ 退出阅读页时写库并**等写库完成再通知书架刷新**（否则书架读到旧进度，再把旧偏移写回去＝撤销改动）。
6. **「从头开始」必须先清零写库再进阅读页**（只改内存副本会被退出保存覆盖）。
7. **用户主动跳转**（目录/书签/进度条）要标记 `userScrolled=true`，否则会被自检当伪值拦掉。

## B. 装载（打开书）

- **必须分片**：2MB 分片读 → **流式解码**（`decodeToString(data,{stream:true})`，跨片的半个汉字由解码器拼）→ 逐片 `normalize` → 最后 join。
  老路（整本 readAll + 整本 decode + 链式 4 次 replace）峰值约 85MB，而且**只有分章阶段报进度** ⇒ 走索引缓存时百分比全程 0%（用户报"卡在 0%"）。
- **流式解码要先探**：老 TextDecoder 不认 `{stream:true}`，分片解会把汉字截成乱码 → `supportsStreamDecode()` 探一次，不支持就回退整本解码。
- **跨片的 `\r\n` 不能拆**：每片末尾若以 `\r` 结尾，把它留到下一片再合并清洗。
- **丢 0 填充**（`dropNulBytes`）**只能在非 UTF-16** 上用（UTF-16 的 ASCII 每字符都带 0x00）。
- **章节索引 sidecar**：`<书文件>.idx`，校验 `文件字节数 + 正文字符数`，文件变了自动失效（抓取追加后重扫）。
- **单章封顶**（`MAX_CHAPTER_CHARS`）：遇到"一整章几百万字"（伪正文）按行切「（续 N）」，否则分页卡死 + 渲染 OOM。
- 装载/分章/分页都不要整本同步跑（会触发系统 `THREAD_BLOCK_3S`，用户看到"白板半天不动"）。
- **目标（未完成）**：正文不许整本常驻。装完 37MB 的书现在仍有 ~148MB PSS（arkts 堆 78.8 + native 52 + 65MB 被换到 swap），目标 ≤40MB —— 做法是把"整本正文"改成"当前章 ±3 章窗口从磁盘读"（sidecar 里补每章字节区间）。

## C. 位置落位（打开书后回到原处）

- 打开瞬间 List 还没铺数据，此时 `scrollTo/scrollToIndex` 会被忽略 ⇒ 必须等真实可滚范围 > 0 再落位。
- `scrollToIndex` 在懒加载 + 块高不一的列表里**落点会偏**（未测量的块只能估）⇒ 用**像素滚动 + 自校准**：真实内容高 ÷ 估算内容高 = 比例，把估算像素换成真实像素，落位后读回第一块核对，不齐继续收敛。
- **收敛必须有上限**（现为 40 次）：实测出现过「位置落位放弃：attempt=41」——空转 1~2 秒白卡、位置还会游走（off 4877→2765）。建议上限收到 3~4 次 + 估算兜底。
- 落位期间不要换章、不要存进度（`placing` 标志）。
- **作用域变更（2026-10-14 定案）**：上下滚动改为**按章切换**（章节不再连排，见 [[01-纯阅功能规格]] §2.1）后，本节的「像素滚动 + 自校准」作用域从「全书」缩小到「**单章之内**」，误差量级随之下降；但**逐块估算高度这一根因不变**，仍按 `docs/fix/scroll_progress_jump/fix-plan.md` 的 FIX-002 / FIX-003 处理。

## D. 左右翻页的纸张效果（PaperTurnPane.ets）

- 结构：底层=新页；上层=正在翻走的旧页（平移 + 绕装订边转 ~10° + 页缘 14px 纸张厚度渐变 + 投影随进度先亮后暗 + 末段 10% 透明）。
- 时长 240ms，Friction 曲线；手势跟手用 `TurnGesture.progressOf(位移, 页宽)`，松手 `shouldTurn(进度, 速度)`（≥35% 或速度 >900 就补完）。
- **`Curve` 不能 `import`**：这个 SDK 的 `@kit.ArkUI` 不导出 `Curve`（用全局的），`import { Curve } from '@kit.ArkUI'` 直接编译失败。
- 接线前请先看文件头注释（state 字段 + 渲染替换 + animateTo 三段）。

## E. 备份到文档 / 导出

- 保存对话框（`DocumentViewPicker.save`）只做两件事：**建一个空文件 + 给 uri**（`file://docs/storage/...`）。
- ❌ `fileIo.copyFile(沙箱路径, uri)` 必失败（`No such file or directory`），用户看到的是"失败提示 + 目录里一个 0B 文件"。
- ✅ 正确做法：`fileIo.open(uri, READ_WRITE|CREATE|TRUNC)` 拿 fd，**1MB 分片**读写；失败时 `fileIo.unlink(uri)` 清掉那个 0B 文件；两端都打 hilog（`backup ok: N bytes` / `backup failed: … uri=`）。

## F. 工程 / 工具链坑

- hvigor 必须两个环境变量：`NODE_HOME`、`DEVECO_SDK_HOME`（不设 → `Invalid value of 'DEVECO_SDK_HOME'`，BUILD FAILED）。
- hdc：本地路径要**反斜杠绝对路径**（`'E:\...\x.hap'`），正斜杠会被当相对路径拼错。
- `install -r` **不会重启** App：装完必须 `aa force-stop` 或从最近任务划掉再开，否则跑的还是旧代码。
- gallery（上架）产品**不要填 `signingConfig`**；上架包签名用 `hap-sign-tool.jar` 手工签 + `verify-app` 验签。
- 真机日志判据：`hilog -x -T reader`（装载 `loaded … chars/chapters`、进度 `save pos:` / `保存进度被拦：原因`、落位 `place blk/place fix/place done`）。

## G. 书源子系统（仅自用版）

- 纯阅规则子集：`class.x/id.x/tag.x/text.x`、`@text/@href/@src/@html/@ownText/@textNodes`、多级 `@`、`||`、`##正则##替换`、`[n]`/`.n`/`!n`。
- **不支持**：`{{ }}` JS、`@js:` 真逻辑、JSONPath `$.data[*]`、`<js>` 解密 —— 带这些的源纯阅永远跑不了（导入时提示，不要假装能用）。
- 检测语义：只有「解析不了/超时/5xx」才算死源（4xx 是防盗链，不算）；关键词固定「小说」。
- 抓取要克制：每站限速、并发批抓、断点续抓、限流退避；「认书名不认源」，换源只补新章；重复段落有专门处理。

**■ H. 官方 API 事实（2026-10-14 逐条核验，改相关代码前先看）**

> 全部取自官方原文（OpenHarmony `docs` 仓 raw md / 华为开发者联盟页面），逐条 grep 命中，**不凭记忆**。
> H.1~H.4 是既有实现的依据补强与新坑；**H.5 是现状缺口**（听书后台会被挂起）。

**▍ H.1 文件读取 API（服务待办 3「按章窗口读」）**

| 事实 | 对本工程的意义 |
|---|---|
| `fs` 文本接口（`readText`/`readTextSync`/`readLines`）的 `encoding` **仅支持 'utf-8'**；`readLines` 读非 utf-8 抛 **13900037** | GBK/GB18030 书只能「按字节读 + 自己解码」——与 03-B 现有做法一致，此条是它的官方依据 |
| `fs` **没有 mmap**（官方 API 参考全文无该符号） | 大文件随机访问只有下面这条正路 |
| 随机/按章读：`createRandomAccessFile()` + `seek()`；或 `lseek(fd, off, WhenceType.SEEK_SET)` + `read(fd, buffer, {length})` | 待办 3 实现「当前章 ±3 章窗口从磁盘读」用这个 |
| ⚠️ **`ReadOptions.offset` 是「基于当前 filePointer 的相对偏移」，不是绝对偏移** | **新坑**：长跳转必须先 `lseek(SEEK_SET)`，否则静默跳错位置 |
| 跨块多字节截断：`decodeToString(u8, {stream:true})` 会把末尾不完整字节序列留在解码器内部缓存 | 03-B 已在用；03-B 记的「设备不认 `{stream:true}`」兜底分支**仍要保留** |

**▍ H.2 编码探测（补 03-B「编码嗅探」的覆盖面）**

- `util.TextDecoder.create(enc, {fatal:true})`：**非法序列会抛错**，正好当探测器用。推荐顺序：`utf-8` → `gb18030`（向下覆盖 gbk/gb2312）→ `big5`；BOM 优先（`EF BB BF` / `FF FE` / `FE FF`）。
- 官方编码白名单（可直接用）：`gbk`、`gb18030`、`gb2312`、`big5`、`shift_jis`、`euc-jp`、`euc-kr`、`utf-8`、`utf-16le/be`、`iso-8859-*`、`windows-125x`。
- 官方**没有**编码自动探测接口 ⇒ 探测必须自研（本工程已有，此条用于核对覆盖面）。

**▍ H.3 列表/目录懒加载（目录几千章场景）**

- `LazyForEach` 的硬约束是 **key 唯一且一致**；官方明确**禁止在 keyGenerator 里用 `stringify`**（大数据场景性能杀手）。
- `List`/`Grid` 的 `cachedCount` **默认只缓存 1 条**（不是「一屏一半」）；屏幕外预加载数量靠它调。
- 自定义子组件要加 `@Reusable` 才进复用池（目录项可考虑）。
- 可变高度的列表项**不影响懒加载**，只影响 `scrollToIndex` 定位精度 —— 这正是 03-C「像素滚动 + 自校准」存在的理由。

**▍ H.4 听书 TTS（Core Speech Kit）**

- 引擎：`@kit.CoreSpeechKit` 的 `textToSpeech`；`createEngine({language, person, online, extraParams})` → `setListener(SpeakListener)` → `speak(text, {requestId, extraParams})`。
- 回调：`onStart` / **`onComplete`** / `onStop` / `onData(audio)` / `onError`；另有 `stop()` / `shutdown()` / `listVoices()`。
- ⚠️ **`requestId` 在同一引擎实例内只能用一次** ⇒ 逐段朗读必须每段生成新 id（否则串句乱播）。
- ⚠️ 单次 `speak` 文本长度有上限（社区口径约 1 万字符量级，**未在官方原文核实，需实测**）⇒ 长段必须切分投喂。
- `online` 决定在线/离线引擎 ⇒ **离线可用性未核实**，直接决定「飞行模式能否听书」。
- 同步口径：**以句/段为原子单位、`onComplete` 是唯一推进信号**；不要用定时器估算进度。

**▍ H.5 后台长时播放（现状缺口 → 见 04 待办 8）**

现状只做了「`onBackground` 心跳 → 立刻写库」（03-A-5），**没有申请长时任务** ⇒ 听书在后台/锁屏可能被系统挂起。连续听书要四件套：

1. `module.json5` 声明 `ohos.permission.KEEP_BACKGROUND_RUNNING`（官方 API 参考仍标「需要权限」）；
2. `backgroundTaskManager.startBackgroundRunning(context, BackgroundMode.AUDIO_PLAYBACK, wantAgent)`，退出时 `stopBackgroundRunning`；**用 `@ohos.resourceschedule.backgroundTaskManager`**（旧 `@ohos.backgroundTaskManager` 自 API 9 起不再维护）；
3. 常驻通知（长时任务必须有），`wantAgent` 指定点击回到阅读页；
4. `AVSession` 登记媒体会话（标题/封面/播放状态）⇒ 锁屏与耳机控制、降低被杀概率。

另需处理音频焦点被抢（来电 / 其他 App）⇒ 暂停 + 从 `tts` 段号续读。
