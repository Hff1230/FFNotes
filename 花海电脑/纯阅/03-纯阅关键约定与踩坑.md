# 纯阅 · 关键约定与踩坑

> 这里每一条都是**用真机事故换来的**。改相关代码前先读，别重新发明。
> 本文 = **红线与口径的唯一来源**；待办与验收判据见 [[04-纯阅待办与验收]]，规格见 [[01-纯阅功能规格]]。

## A. 红线与总口径

1. **任何情况下不许损坏阅读进度**——写库前必须自检，宁可这一次不写：位置三件套（`offset` + `chapterTitle` + `progress`）里任何一个对不上，都按"伪值"处理。
2. **位置锚（三态回退）**：恢复位置时
   ① 章号能从偏移推出、且与记下的章节名一致 → 用偏移（最精确）；
   ② 两者冲突（正文被重排/续抓/换源）→ **以章节名为准**；
   ③ 偏移越界 → 章节名 → 「进度 × 源目录总章数」→ 最后退到记下的章号。
3. **进度的分母用「源目录总章数」**（`srcTotal`），不用"已抓章数"——否则补章后进度会往回掉。
4. **保存前自检（四闸，含 2026-10-14 定案的例外与白名单）**：伪值一律不覆盖库里的好位置。
   - **G1**：自打开以来**无任何用户交互**（`userTouched=false`）→ `saveProgress()` 直接 return，只写日志。
     - **例外（听书）**：**TTS 播放中视为"用户已交互"**（用户点播放即视为授权写入），听书的自动推进/自动跨章位置照常落库；仍走 G3/G4 的伪值检查。
     - 理由：听书无屏幕交互，G1 硬拦会让**听了半小时的进度不落库**（01 §2.4 要求"切章自动接续"）。
   - **G2**：无用户交互期间**不许因滚动推导改 `curIndex`**（只有真人滚过/翻过才认）。
   - **G3**：`!userScrolled` 且 **jumped ≥ 1** 且偏移 ≈ 新章开头（`off == ch.start`）→ 判伪值丢弃（现实现只拦 >1 章，**必须改成 ≥1**）。
     - **白名单（不算伪值）**：位置变化**源于**「下一章 / 上一章」过渡按钮点按、目录/书签/进度条跳转、听书自动跨章时，`off == ch.start` 属**正常**。
   - **G4**：`placing` 期间（落位未收敛）**禁止写库**；退出时若仍在 `placing`，按"最后一次已确认的 `offset`"写。
5. **落库时机**：`aboutToDisappear`（退出阅读页）**不够**——用户直接回桌面/切走不会触发。必须三条一起：
   ① `EntryAbility.onBackground` 打 `AppStorage.setOrCreate('appBgTick', Date.now())` 心跳 → 阅读页收到立刻写库；
   ② 阅读中滚动/翻页停稳 ≥8 秒节流落库；
   ③ 退出阅读页时写库并**等写库完成再通知书架刷新**（否则书架读到旧进度，再把旧偏移写回去＝撤销改动）。
6. **「从头开始」必须先清零写库再进阅读页**（只改内存副本会被退出保存覆盖）。
7. **用户主动跳转**（目录/书签/进度条）要标记 `userScrolled=true`，否则会被自检当伪值拦掉。

## B. 装载（打开书）

- **必须分片**：2MB 分片读 → **流式解码**（`decodeToString(data,{stream:true})`，跨片的半个汉字由解码器拼）→ 逐片 `normalize` → 最后 join。
  老路（整本 readAll + 整本 decode + 链式 4 次 replace）峰值约 85MB，而且**只有分章阶段报进度** ⇒ 走索引缓存时百分比全程 0%（用户报"卡在 0%"）。
- **流式解码要先探**：老 TextDecoder 不认 `{stream:true}`，分片解会把汉字截成乱码 → `supportsStreamDecode()` 探一次，不支持就回退整本解码。
- **跨片的 `\r\n` 不能拆**：每片末尾若以 `\r` 结尾，把它留到下一片再合并清洗。
- **丢 0 填充**（`dropNulBytes`）**只能在非 UTF-16** 上用（UTF-16 的 ASCII 每字符都带 0x00）。
- **章节索引 sidecar**：`<书文件>.idx`，校验 `文件字节数 + 正文字符数`，文件变了自动失效（抓取追加后重扫）；后续要扩成「每章字节区间 + 块索引表」（见 [[02-纯阅工程与架构]] §2）。
- **单章封顶**（`MAX_CHAPTER_CHARS`）：遇到"一整章几百万字"（伪正文）按行切「（续 N）」，否则分页卡死 + 渲染 OOM。
- 装载/分章/分页都不要整本同步跑（会触发系统 `THREAD_BLOCK_3S`，用户看到"白板半天不动"）。
- **目标（未完成，判据在 04）**：正文不许整本常驻。装完 37MB 的书现在仍有 ~148MB PSS（arkts 堆 78.8 + native 52 + 65MB 被换到 swap），目标 ≤40MB —— 做法是"当前章 ±3 章窗口从磁盘读"（`.idx` 补每章字节区间）。

## C. 位置落位（打开书后回到原处）

- 打开瞬间 List 还没铺数据，此时 `scrollTo/scrollToIndex` 会被忽略 ⇒ 必须等真实可滚范围 > 0 再落位。
- `scrollToIndex` 在懒加载 + 块高不一的列表里**落点会偏**（未测量的块只能估）⇒ 用**像素滚动 + 自校准**：真实内容高 ÷ 估算内容高 = 比例，把估算像素换成真实像素，落位后读回第一块核对，不齐继续收敛。
- **收敛必须有上限**：现为 40 次（实测出现过「位置落位放弃：attempt=41」，空转 1~2 秒白卡、位置还会游走 off 4877→2765）⇒ **收到 3~4 次**，不齐则用估算兜底并把该次落位标记为"未精确"。
- 落位期间不要换章、不要存进度（`placing` 标志，配 A-4 的 G4）。
- **作用域变更（2026-10-14 定案：上下滚动改「按章切换」）**：列表一次只装**当前章**的块 ⇒
  - 「像素滚动 + 自校准」作用域从「全书」缩到「**单章之内**」，比例分母是**本章**估算内容高，误差量级随章内块数下降；
  - **章号由"当前章"状态直接给出，不再从像素推导**；
  - **逐块估算高度这一根因不变** ⇒ 仍按 FIX-002（位置来源改可见项索引）/ FIX-002b（`keyGenerator` 稳定化 + 同源块高）处理；
  - 落位失败也不许在无交互期改写 `curIndex`（A-4 的 G2）。

### C.1 滚动模式三个「看起来像玄学」的坑（2026-10-14 定案，均已修）

1. **页码胶囊恒显示「本章第 1 页」（用户报：始终 1/11）**
   根因：窗口一次装 ≈20 章连排，`currentOffset()` 算出的全局偏移落进**别的章**时会被夹回 `curIndex` 章的区间 → 章内页码恒为 1，总页数还是当前章的 →「1/11」。
   修法：滚动模式窗口**只渲染当前章**（`windowRange()` 恒 `[center,center]`）。**别再恢复多章连排**，否则这个 bug 必然复发。
2. **滚着滚着直接跳章（用户报：滚动模式直接滚到第四章了）**
   根因：`maybeShiftWindow()` 在滚动模式也会「按视口顶部所在章换窗口」，等于自动换章。
   修法：滚动模式该函数**直接 return**；换章只由章首/章末按钮、目录/书签、听书驱动 —— 一章滚到底**自然停住**（`EdgeEffect.Spring`）。
3. **切章后页码还留着上一章的数字（1/23 出现在章末）**
   根因：`updatePageLabel()` 在切章那一刻就算过一次（此时 `pageStarts` 还是旧章、滚动还在顶部），而 `pageLabel` 值没变化 ⇒ 之后没人再刷新它。
   修法：`gotoChapter()` / `gotoOffset()` 里**延后 300ms** 强制刷一次。凡「先改状态再等布局」的位置类显示，都要按这个套路补刷新。

4. **切章后停在「半中腰」，看不到本章最上面（用户报）**
   根因：**`LazyForEach` 数据源变化时，List 的滚动偏移不会被框架重置** —— 切章那一瞬它沿用上一章的偏移量（实测 `curY=8026 off=13661`，正落在新章中间；新章更短时被夹到新章 `maxScroll`）。
   而原来只靠「位置落位」把它纠回 0，**落位在用户手动滚动过之后会放弃**（`位置落位放弃`）⇒ 纠不回来，就成了用户看到的现象。
   修法：`settleChapterScroll(toEnd)` —— 切章后 300ms（数据提交完）**自己补一次 `scrollTo`**（章首→0、章末→`maxScroll`）＋ 刷页码＋刷高亮，**不依赖落位是否成功**。
   ⚠️ 凡「换数据源后要回到顶部」的列表，都要显式补一次定位，别指望框架或落位。

### C.3 听书（TTS）的三个坑（2026-10-14 定案，均已修）

1. **听书时「屏幕内只显示一句」** —— 不是渲染 bug：**听书设置面板没收起**，面板霸占下半屏（页模式还会按 `blockedH()` 把分页高度一起压掉）。
   修法：点「开始朗读」后自动 `panel = ''` + `ttsPanelVp = 0`（@Watch → `onPanelHChanged` 重分页/重算高亮），正文恢复满屏。
2. **高亮比声音早一句（用户报「高亮的是下一句」）** —— 同一次 `speak` 会回调**两次**：`type 0 = 合成结束`（PCM 刚生成、音频还在播）、`type 1 = 播报结束`。旧代码不做 type 判断、只按 `requestId` 去重 ⇒ **合成一结束就 `cur++`**，高亮抢先跑到下一句。
   修法：`type 0` 只登记兜底定时器、**不推进**；`type 1` 才推进。
3. **兜底**：真机上「播报结束」偶发不来（旧注释：有时只给其中一次）⇒ 收到 `type 0` 时按「字数 × 每字耗时（1x ≈ 4 字/秒）」估时长挂定时器，到点仍没等到 `type 1` 才推进 —— **宁可晚一点，不许抢拍**，也不能把听书卡死。

⚠️ 自查日志：正确顺序是 `BookSpeaker: seg synth-done(不推进) pure_N` 紧跟 `seg done pure_N type=1`；只有前者、既没有后者也没有 `synth fallback 推进` = 卡住了。

### C.4 朗读断句（TTS 分段）三级规则（2026-10-14 定案）

用户口径："按句号分割的话，一句话可能太长；普通的逗号、省略号可以单独拆；**但是双引号中间说的话不要再拆**。"

| 级别 | 规则 | 原因 |
|---|---|---|
| ① 一级 | 句末标点（`。！？…；`）/ 换行 | 自然断句 |
| ② 二级 | 累计 ≥ `SOFT_MIN`(24 字) 时，在句中停顿标点（`，、：`）处喘口气 | 按句号分会出现几十上百字的段：TTS 请求长、暂停迟钝、**高亮粒度粗、跨页判断也跟着变粗** |
| ③ 硬上限 | `SEG_MAX` 90 字（引号内 150 字） | 无标点长串兜底；引号内放宽以免动对话 |
| ★ 引号 | **开引号本身就是断点（对话自成一段）**；**引号内不按逗号/句末/换行拆** | 落实「双引号中间说的话不要拆」；顺带让「对白/旁白语气区分」更准 |
| 收尾 | 「只有标点的段」（如闭引号后剩下的「，」「……」）并进上一段 | 别让 TTS 念一个孤零零的逗号 |

⚠️ 高亮粒度 = 段粒度：二级断句会让高亮在一句话内**逐小句推进**（跟读更细），不是 bug。
**实测（`剑来` 前 50 万字）**：段数 13442 → 19414；最长 110 → 152（超长对话安全阀）；平均 28.1 → 24.4；**超过 40 字的段 26% → 7.8%**；**4348 段引号对话中 0 段被意外拆开**（仅 203 段是超过 150 字的超长对话，属安全阀）。真机自检日志：`BookSpeaker: segs=N maxLen=M avgLen=K`。

### C.5 听书跟随的两种「不跟」及修法（2026-10-14）

1. **翻页模式：一句话跨页，屏幕不翻**
   现象：高亮被页底切断，声音已经念到下一页的字，屏幕还停在上一页。
   修法：`followSpeech` 里算 `p`（段首所在页）与 `pEnd`（段尾所在页）；跨页时按**字数占比**决定：占比 ≤50% 立即翻到 `pEnd`，否则按占比估时（`estSegMs`）**念到分界点再翻**（`pageTurnTimer`，换段/停播必须 `cancelPageTurn()`）。
   日志：`page turn: seg=.. p=53 pEnd=55 onP=22 total=97 ratio=23 est=25220` → `page turn done: page=56/150`。
2. **滚动模式：高亮跑出屏幕，屏幕不动**
   根因：可见性判定只看了「**段首**块在不在可视带」，段一长（对话 60~150 字）段首刚在带上沿、段尾早已出屏 ⇒ 判定"已可见"不滚。
   修法：改按**段尾**判定（整段在带内才不滚）；整段装不下时先顶段首，念到后半段再把段尾带进视野（`followTailTimer`，按段内时间估 50% 处触发）。滚动统一走 `scrollToShow()` 并回读校正（`follow check: diff=21`，不累积）。
   ⚠️ 判定用打点：`hrel`（高亮起点块距视口顶像素）、`hrelEnd`（高亮**终点**块距顶像素）、`band`（可视带高）；**0 ≤ hrel 且 hrelEnd ≤ band 才叫"高亮在屏内"**。

### C.5.1 听书跟读「翻页抖动」——同一病根：两个目标打架（2026-10-14 修）

- 现象：翻页模式页码来回跳（实测 `page turn done: 42/89 → 41/89 → 42/89`），滚动模式 curY 在几十像素间抖。
- 根因：**段级对齐**（把页面/视口拉回"本段起点"）与**跟随推进**（按语速预测往前推）目标不同，两边轮流执行。
- 修法（一个目标原则）：
  · 翻页模式：段首对齐只在「当前页已不在本段的页范围 `[p, pEndPage]`」时才执行；段内推进只由 `followFrontier` 驱动，且**只往前翻**（`p > pageIndex`）。
  · 滚动模式：段首/段尾对齐（旧 `followSpeechScroll`）**停用**，统一走 `followFrontier`。
  · 原「按两页字数占比定时翻页」删除（与 600ms 跟随定时器重复，是重复翻页的来源）。
- 判据：翻页模式跑一段听书，`hi diag` 的 `page` 序列**单调不减**，且 `hpage == page`（屏幕页 = 高亮页）。实测 7→7→8→8→9→9→10 全单调。

### C.6 后台听书的进度（2026-10-14 用户要求）

- 现象：后台/息屏听了一章，回来位置还在老地方。
- 根因：进度一直用 `currentOffset()`（滚动模式由 `curY/maxScroll` 推）——**后台时视口不给实时滚动值**，它就冻在旧位置；再加上「位置未稳定 + 没用户滚动」的伪值拦截，保存还会被整段拦掉。
- 修法：`speechOffset()` = 章起点 + 当前朗读段偏移（`hiSegFrom`，就是高亮的那一段），听书期间保存**以它为准**；并把 `ttsPlaying` 计入「已交互」，不再被 `posUnsettled` / 伪值检查拦。
- 验证：后台读到 `hi=1219..1246` → 强杀重开 `restore pos: 按偏移 idx=5 第六章 下签 off=19470`（布局值当时冻在 19318，说明存的确实是朗读位置）。
- ⚠️ 打点别糊：`save pos` 那行日志打印的是 `currentOffset()`（布局值），**看不出实际存的是哪个**——后台排查时以「重开落位」为准，或看 `tts=Y` 标记。

### C.7 构建报「Failed to delete ... entry-default-signed.hap」

- 不是权限问题，是**你自己（或别的工具）还开着这个 hap 的句柄**。踩过：用 `zipfile.ZipFile(hap)` 核验包内代码后没关，Hermes 的 python 会话一直占着它 → `hvigor` 删不掉旧包、直接 BUILD FAILED（而且失败得很快，容易误判成"编译问题"）。
- 定位：`python -c "import psutil; [print(p.pid,p.info['name']) for p in psutil.process_iter(['pid','name']) if any('entry-default-signed.hap' in f.path.lower() for f in p.open_files())]"`。
- 规矩：核验包内代码一律用 `with zipfile.ZipFile(...) as z:`（或读完立刻 `close()`）。

## D. 左右翻页的纸张效果（PaperTurnPane.ets）

- 结构：底层=新页；上层=正在翻走的旧页（平移 + 绕装订边转 ~10° + 页缘 14px 纸张厚度渐变 + 投影随进度先亮后暗 + 末段 10% 透明）。
- 时长 240ms，Friction 曲线；手势跟手用 `TurnGesture.progressOf(位移, 页宽)`，松手 `shouldTurn(进度, 速度)`（≥35% 或速度 >900 就补完）。
- **`Curve` 不能 `import`**：这个 SDK 的 `@kit.ArkUI` 不导出 `Curve`（用全局的），`import { Curve } from '@kit.ArkUI'` 直接编译失败。
- 接线前请先看文件头注释（state 字段 + 渲染替换 + animateTo 三段）。

## E. 备份到文档 / 导出

- 保存对话框（`DocumentViewPicker.save`）只做两件事：**建一个空文件 + 给 uri**（`file://docs/storage/...`）。
- ❌ `fileIo.copyFile(沙箱路径, uri)` 必失败（`No such file or directory`），用户看到的是"失败提示 + 目录里一个 0B 文件"。
- ✅ 正确做法：`fileIo.open(uri, READ_WRITE|CREATE|TRUNC)` 拿 fd，**1MB 分片**读写；失败时 `fileIo.unlink(uri)` 清掉那个 0B 文件；两端都打 hilog（`backup ok: N bytes` / `backup failed: … uri=`）。

## F. 工程 / 工具链坑

- hvigor 必须两个环境变量：`NODE_HOME`、`DEVECO_SDK_HOME`（不设 → `Invalid value of 'DEVECO_SDK_HOME'`，BUILD FAILED）。
- hdc：本地路径要**反斜杠绝对路径**（`'E:\...\x.hap'`），正斜杠会被当相对路径拼错。
- `install -r` **不会重启** App：装完必须 `aa force-stop` 或从最近任务划掉再开，否则跑的还是旧代码。
- gallery（上架）产品**不要填 `signingConfig`**；上架包签名用 `hap-sign-tool.jar` 手工签 + `verify-app` 验签。
- 真机日志判据：`hilog -x -T reader`（装载 `loaded … chars/chapters`、进度 `save pos:` / `保存进度被拦：原因`、落位 `place blk/place fix/place done`）。
- **Obsidian 库写入**：覆盖已有文档时若被写入守卫拦（曾用分页方式读过），用"写 `.next` 再 `mv -f` 覆盖"的办法（见 [[05-纯阅文档地图与维护规则]] §六）。

## G. 书源子系统（仅自用版）

- 纯阅规则子集：`class.x/id.x/tag.x/text.x`、`@text/@href/@src/@html/@ownText/@textNodes`、多级 `@`、`||`、`##正则##替换`、`[n]`/`.n`/`!n`。
- **不支持**：`{{ }}` JS、`@js:` 真逻辑、JSONPath `$.data[*]`、`<js>` 解密 —— 带这些的源纯阅永远跑不了（导入时提示，不要假装能用）。
- 检测语义：只有「解析不了/超时/5xx」才算死源（4xx 是防盗链，不算）；关键词固定「小说」。
- 抓取要克制：每站限速、并发批抓、断点续抓、限流退避；「认书名不认源」，换源只补新章；重复段落有专门处理。
- **抓取正文的整理（2026-10-14 定案）**：抓取路径必须**先提纯再落盘**，并把**未整理的原始正文**写进 `<书>.raw`（否则整理不可回溯）。口径见 [[01-纯阅功能规格]] §2.7。

## H. 官方 API 事实（2026-10-14 逐条核验，改相关代码前先看）

> 全部取自官方原文（OpenHarmony `docs` 仓 raw md / 华为开发者联盟页面），逐条 grep 命中，**不凭记忆**。
> H.1~H.4 是既有实现的依据补强与新坑；**H.5 是现状缺口**（听书后台会被挂起）。

### H.1 文件读取 API（服务待办 9「按章窗口读」）

| 事实 | 对本工程的意义 |
|---|---|
| `fs` 文本接口（`readText`/`readTextSync`/`readLines`）的 `encoding` **仅支持 'utf-8'**；`readLines` 读非 utf-8 抛 **13900037** | GBK/GB18030 书只能「按字节读 + 自己解码」——与 03-B 现有做法一致，此条是它的官方依据 |
| `fs` **没有 mmap**（官方 API 参考全文无该符号） | 大文件随机访问只有下面这条正路 |
| 随机/按章读：`createRandomAccessFile()` + `seek()`；或 `lseek(fd, off, WhenceType.SEEK_SET)` + `read(fd, buffer, {length})` | 待办 9 实现「当前章 ±3 章窗口从磁盘读」用这个 |
| ⚠️ **`ReadOptions.offset` 是「基于当前 filePointer 的相对偏移」，不是绝对偏移** | **新坑**：长跳转必须先 `lseek(SEEK_SET)`，否则静默跳错位置 |
| 跨块多字节截断：`decodeToString(u8, {stream:true})` 会把末尾不完整字节序列留在解码器内部缓存 | 03-B 已在用；03-B 记的「设备不认 `{stream:true}`」兜底分支**仍要保留** |

### H.2 编码探测（补 03-B「编码嗅探」的覆盖面）

- `util.TextDecoder.create(enc, {fatal:true})`：**非法序列会抛错**，正好当探测器用。推荐顺序：`utf-8` → `gb18030`（向下覆盖 gbk/gb2312）→ `big5`；BOM 优先（`EF BB BF` / `FF FE` / `FE FF`）。
- 官方编码白名单（可直接用）：`gbk`、`gb18030`、`gb2312`、`big5`、`shift_jis`、`euc-jp`、`euc-kr`、`utf-8`、`utf-16le/be`、`iso-8859-*`、`windows-125x`。
- 官方**没有**编码自动探测接口 ⇒ 探测必须自研（本工程已有，此条用于核对覆盖面）。

### H.3 列表 / 目录懒加载（目录几千章场景）

- `LazyForEach` 的硬约束是 **key 唯一且一致**；官方明确**禁止在 keyGenerator 里用 `stringify`**（大数据场景性能杀手）。
- `List`/`Grid` 的 `cachedCount` **默认只缓存 1 条**（不是「一屏一半」）；屏幕外预加载数量靠它调。
- 自定义子组件要加 `@Reusable` 才进复用池（目录项可考虑）。
- 可变高度的列表项**不影响懒加载**，只影响 `scrollToIndex` 定位精度 —— 这正是 03-C「像素滚动 + 自校准」存在的理由。
- 位置来源改造可用：`onScrollVisibleContentChange`、`getVisibleListContentInfo(x,y)`、`maintainVisibleContentPosition(true)`（**本工程当前均未使用**，属全新接入）。

### H.4 听书 TTS（Core Speech Kit）

- 引擎：`@kit.CoreSpeechKit` 的 `textToSpeech`；`createEngine({language, person, online, extraParams})` → `setListener(SpeakListener)` → `speak(text, {requestId, extraParams})`。
- 回调：`onStart` / **`onComplete`** / `onStop` / `onData(audio)` / `onError`；另有 `stop()` / `shutdown()` / `listVoices()`。
- ⚠️ **`requestId` 在同一引擎实例内只能用一次** ⇒ 逐段朗读必须每段生成新 id（否则串句乱播）。
- ⚠️ 单次 `speak` 文本长度有上限（社区口径约 1 万字符量级，**未在官方原文核实，需实测**）⇒ 长段必须切分投喂。
- `online` 决定在线/离线引擎 ⇒ **离线可用性未核实**，直接决定「飞行模式能否听书」。
- 同步口径：**以句/段为原子单位、`onComplete` 是唯一推进信号**；不要用定时器估算进度。
- **进度相关**：TTS 自动推进期间必须允许落库（A-4 的 G1 例外），否则听书进度丢失。

### H.5 后台长时播放（现状缺口 → 见 04 待办 19）

现状只做了「`onBackground` 心跳 → 立刻写库」（03-A-5），**没有申请长时任务** ⇒ 听书在后台/锁屏可能被系统挂起。连续听书要四件套：

1. `module.json5` 声明 `ohos.permission.KEEP_BACKGROUND_RUNNING`（官方 API 参考仍标「需要权限」）；
2. `backgroundTaskManager.startBackgroundRunning(context, BackgroundMode.AUDIO_PLAYBACK, wantAgent)`，退出时 `stopBackgroundRunning`；**用 `@ohos.resourceschedule.backgroundTaskManager`**（旧 `@ohos.backgroundTaskManager` 自 API 9 起不再维护）；
3. 常驻通知（长时任务必须有），`wantAgent` 指定点击回到阅读页；
4. `AVSession` 登记媒体会话（标题/封面/播放状态）⇒ 锁屏与耳机控制、降低被杀概率。

另需处理音频焦点被抢（来电 / 其他 App）⇒ 暂停 + 从 `tts` 段号续读。
