# 纯阅 · 优化方案（性能 / 用户体验 / 视觉体验）

> **怎么读**：每条 = **现状（实测/代码事实）→ 目标指标 → 做法 → 验收判据 → 代价与风险**。
> **纪律**：标注「实测」的是真机量到的；标注「代码事实」的是 grep/读码确认的；**没有实测数字的项写明"待建基线"**，不编数。
> **优先级**：`P0` 现在就做（红线/用户已报）｜`P1` 高收益低成本｜`P2` 体验打磨 / 依赖前项。

## 一、性能

### P0-1 正文不许整本常驻（内存 148MB → ≤40MB）
- **现状（实测）**：打开 37MB《剑来》后 `hidumper --mem` PSS ≈ **148MB**（arkts 堆 78.8MB + native 52MB + 图形/GL），另有 **≈65MB 被换到 swap**；小说正文整本常驻内存。
- **目标**：PSS **≤40MB**；换章无卡顿（帧率不低于基线）；连续读 30 分钟内存不涨（无泄漏）。
- **做法**：
  1. `.idx` sidecar **一次定好格式**：除现有「字节数 + 字符数」校验外，补 **每章字节区间** 与 **块索引表**（与复核文档 P1-8 合并设计）；
  2. 用 `createRandomAccessFile()/lseek + read` 按章读；窗口 = **当前章 ±3 章**，滚出窗口即释放；
  3. normalize 清洗**就地做**（不产生第二份整本副本），分章/建索引放后台。
- **验收判据**：`hidumper --mem <pid>` PSS ≤40MB（同机同书）；连续翻 50 章内存不单调上涨；翻章首帧 ≤1 屏白屏时间（无肉眼可见停顿）。
- **代价/风险**：**中高**——碰装载与位置锚两条主干，必须与 FIX-002 同步动 `.idx`；建议单独一批、独立回滚。

### P0-2 列表渲染手段补齐（当前基本没用）
- **现状（代码事实）**：`cachedCount` 仅 **2 处**；`@Reusable` **0 处**；`childrenMainSize` **0 处**；正文/目录 `LazyForEach` **未写 `keyGenerator`**（默认按 index 作 key）。
- **目标**：滚动帧率不降（基线见 §四）；**位置索引稳定**（补章/换源后不错位）；内存不因渲染涨。
- **做法**：① 给 `LazyForEach` 显式 `keyGenerator`（键含「章号 + 块序号」，**禁 `stringify`**，官方明令）；② 列表项加 `@Reusable`；③ `cachedCount` 提到 3~5（按实测调）；④ 块高做到渲染同源后接 `childrenMainSize`。
- **验收判据**：抓取补章后重进阅读页，位置**无系统性偏移**；滚动帧率 ≥ 基线；`@Reusable` 生效（日志/Profiler 可见复用）。
- **代价/风险**：低（独立小改），但与 FIX-002 的映射强相关 → 归入复核文档 **FIX-002b**。

### P1-3 包体与资源瘦身
- **现状（实测）**：签名 HAP **1,883,398 字节**；资源里 `app_icon.png` **235.3KB**、`background.png` **89.8KB**、`startIcon.png` 20.9KB —— 单张图标就占了包体 **12%**。
- **目标**：包体 **≤1.7MB**（先砍 200KB+）；启动图加载不超 1 帧。
- **做法**：图标/启动图转 **webp**（或调色板 PNG），按密度出多套；`background.png` 换成纯色/渐变或矢量绘制；核对 `resources/base/media` 无冗余大图。
- **验收判据**：HAP 体积对比（前后数字）+ AGC 上传包大小；真机首屏可见启动图（不黑屏）。
- **代价/风险**：**低**，纯资源替换，无逻辑风险（上架包需重新出）。

### P1-4 打开书"先出正文，再补全"
- **现状（实测）**：21.9MB《凡人修仙传》≈2 秒、37MB《剑来》≈3 秒进正文；装载百分比虽已在动（本轮刚修），但**用户仍是"盯着百分比等"**。
- **目标**：**首次可见正文 ≤1.5s**；进度后台继续跑不阻塞阅读。
- **做法**：索引 sidecar 命中时**先只准备"当前章 + 相邻 3 章"**（配 P0-1 的按章读），全文索引/分章放后台；首屏给**骨架屏**（书名 + "正在准备正文…"）而不是空白。
- **验收判据**：从点击到出现正文文字的耗时（录屏数帧）；后台索引完成后位置不跳（配合 FIX-001 的护栏）。
- **代价/风险**：中（依赖 P0-1 的窗口化）；与位置落位耦合，需一起回归。

### P1-5 书源抓取的省电/发热
- **现状（代码事实）**：并发批抓 + 每站限速 + 限流退避（`HostLimiter.penaltyMs` 最长 8s 退避）已实现；但**没有"仅在充电/WiFi 全速"的策略**。
- **目标**：抓 100 章不烫手（机身温度不超基线 +5℃）、掉电可控；后台不被系统杀。
- **做法**：① 非充电/移动网络时**降到单并发 + 每 N 章让出 200ms**；② 抓取进度落库后可随时暂停/续抓（已有断点续抓，补 UI 按钮）；③ 长时任务（见 P2-6）。
- **验收判据**：抓 100 章的耗电与温度对比（同机同源）；后台 10 分钟未被杀。
- **代价/风险**：低。

### P2-6 听书后台长时任务（03-H.5 提到，仍未做）
- **现状（代码事实）**：TTS 只有"心跳落库"，**未申请长时任务** → 锁屏/后台可能被挂起；`SEG_MAX=110` 字分段（为暂停响应速度）。
- **做法**：`module.json5` 申请后台模式 + `wantAgent` 通知栏媒体控制（播放/暂停/上一段）；锁屏继续播。
- **判据**：锁屏播放 10 分钟不断；通知栏可控制；耗电曲线对比。
- **代价/风险**：中（需上架政策匹配，说明用途）。

## 二、用户体验

### P1-7 打开就回到"刚才那一行"（红线延伸）
- **现状（实测）**：进度会跳到下一章开头（已有日志证据），落位尝试最多 **40 次**、实测出现过 `attempt=41` 放弃（1~2 秒白卡 + 位置游走 off 4877→2765）。
- **做法**：按 [[2026-10-14-口径复核与处置]] 的 **P0-1/P0-2 定稿口径** + FIX-001 四闸 + 收敛上限 3~4；落位期给一行轻提示（"正在恢复位置…"）而不是空白。
- **判据**：见 [[04-纯阅待办与验收]] 阅读进度验收（回到原处误差 ≤1 屏；书架百分比不跳不变）。

### P1-8 书架管理升级（现在只支持"长按单个"）
- **现状（代码事实）**：长按菜单 = 续读/从头读/移动/分享/备份到文档/移出书架（单个操作）；无多选、无排序、无搜索。
- **做法**：① **多选模式**（批量删除/移动/分享）；② 排序（最近阅读 / 添加时间 / 大小）；③ 书名搜索；④ 文件夹拖拽移动。
- **判据**：50 本书下批量移动/删除 ≤2 秒完成；排序后刷新一致。
- **代价**：中（Index.ets 界面重构）。

### P1-9 书架信息"一眼可读"
- **现状（代码事实）**：封面是**标题哈希取色块**（`coverColor()`），进度百分比与章名信息展示较简。
- **做法**：书卡显示「**续读 42% · 第 12 章 · 张三**」两行；抓取中的书显示「**抓取中 120/2448**」；未读的书显示文件大小/格式。

### P1-10 手势与操作一致性
- **建议**：① 左/右边缘**点击翻页**、中间点击**呼出菜单**（现状已单击翻页，需确认分区）；② 顶部下拉=目录、底部下拉=设置（可选）；③ **长按选句 → 摘录/分享/加书签**（书签摘录已有，补"选句"）。
- **代价**：中；**风险**：与翻页冲突 → 先做手势分区实验再全量。

### P2-11 无障碍（现状几乎为零）
- **现状（代码事实）**：`accessibilityText` 全工程仅 **1 处**（在 Reader.ets），书架 **0 处**。
- **做法**：给所有图标按钮、进度条（"已读 42%"）、翻页按钮加无障碍文案；对比度检查（主题 × 字号）。
- **判据**：TalkBack 走查一遍主要路径无"未命名按钮"。

### P2-12 首次使用引导
- **现状**：已有《使用说明》书（11 语言，自动入书架）。
- **做法**：首启 3 步气泡（导入书 → 翻页/滚动 → 听书），可跳过，只出现一次。

## 三、视觉体验

### P1-13 阅读页排版精细化
- **现状（代码事实）**：4 套主题（纸张 `#F7F4EE` / 米黄 / 护眼 / 夜间 `#14161A`）；`fontSize=18`、`lineHeight=1.7` 可调；面板自绘。
- **做法**：① 字号/行距/边距**三档滑杆**（现在是否为档位需确认）；② 开关：**段首缩进 2 字符**、段间距、两端对齐；③ 字体族选择（内置字体需评估包体）；④ 夜间模式改**纯黑 + 低亮度**（OLED 省电），并支持**随系统深色自动切换**。
- **判据**：同字号下改行距/缩进不引起位置漂移（配合 FIX-003 的尺寸同步）。
- **代价**：中；**依赖 P0-2 的块高同源**，否则顺序会乱。

### P1-14 封面视觉（现在是纯色块）
- **做法**：渐变底（按标题哈希取色相）+ **书名大字排版**（衬线/书宋）+ 作者小字 + 底部进度条；epub 有封面图则优先用真封面，txt 用生成封面（可选 3~4 套模板）。
- **判据**：与"高级感"基线对比（截图评审）；生成 50 本不卡（懒生成 + 缓存）。

### P2-15 翻页动效与官方档对比（关联待拍板 5.1）
- **现状（代码事实）**：自研 `PaperTurnPane`：240ms、绕装订边转 ~10°、页缘 14px 厚度、投影渐变；**未接线**。
- **做法**：接线后与官方 Reader Kit 的**仿真档**在真机并排对比（同一本书、同一段），看"纸感"与参数可调性。
- **依赖**：⚠️ 若最终选官方 Reader Kit 接管解析/分页/渲染，则本项与 P1-13 的**精排部分**都不必自研（见 04 §5.1）。

### P2-16 状态栏与沉浸式
- **建议**：阅读页**沉浸式**（隐藏系统状态栏/导航条，点击呼出）；底部信息条保留「章名 + 第 N/M 页 + 百分比」；可选**左边缘上下滑调亮度、右边缘调字号**（需防误触）。
- **风险**：手势冲突 → 与 P1-10 一起做手势实验。

### P2-17 动效与配色统一
- **做法**：全应用动效统一为「菜单/面板 200ms、翻页 240ms、曲线 Friction」；主色提取为常量（避免各页面各写一套灰阶）；**禁止一帧硬切**（已写进 01 §2.1 规格）。

## 四、指标看板（先量后改）

| 指标 | 现状 | 目标 | 怎么量 |
|---|---|---|---|
| 内存 PSS（开 37MB 书） | **148MB（实测）** | ≤40MB | `hidumper --mem <pid>` |
| swap | **≈65MB（实测）** | 显著下降 | 同上 |
| 打开书到出正文 | 21.9MB≈2s / 37MB≈3s（实测） | 首屏 ≤1.5s | 录屏数帧 |
| 落位收敛次数 | 上限 40，实测 `attempt=41` 放弃 | ≤3~4 | `hilog -x -T reader` 的 `place attempt` |
| 包体 | **1,883,398 B（实测）** | ≤1.7MB | HAP 文件大小 |
| 滚动帧率 | **待建基线** | 基线或更好 | DevEco Profiler |
| 功耗/温度（抓取 100 章、听书 30 分钟） | **待建基线** | 基线或更好 | 系统电量/温度 |
| 无障碍文案覆盖 | Reader 1 处 / 书架 0 处（代码事实） | 主要路径 100% | 代码核对 + 走查 |

> ⚠️ **帧率与功耗必须先建基线**（改之前量一次），否则"优化了"没有判据——这也符合本项目的验收纪律。

## 五、优先级与排期建议

| 顺序 | 事项 | 依赖 | 建议 |
|---|---|---|---|
| 1 | **先建基线**：帧率、功耗、打开书耗时、内存曲线 | 无 | 一小时的事，收益是后面所有优化的判据 |
| 2 | P0-1 内存窗口化 ＋ P0-2 列表手段（含 FIX-002b） | `.idx` 格式一次定好 | 与 FIX-002 合并设计、分批上线 |
| 3 | P1-3 包体瘦身 / P1-4 首屏 | 无 | 低成本、可独立出包 |
| 4 | P1-7 位置可靠（FIX-001 四闸） | 复核文档 P0-1/P0-2 口径 | 红线优先，与上述并行 |
| 5 | P1-8/9 书架管理 + 信息 / P1-13/14 排版 + 封面 | P0-2 的尺寸同源 | 体验批次 |
| 6 | P2 项（听书长时任务、手势、无障碍、沉浸式、引导） | 视拍板 | 打磨批次 |
