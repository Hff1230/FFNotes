## 1. 现象（用户真机 2026-10-16）

滚动模式下滚到章末：**「上一章 / 下一章」按钮还没露出来时页码是 `47 / 49`；按钮一露出来，直接变成 `49 / 49`** ——
`48 / 49` 从不出现（用户原话：「没看到上一章、下一章按钮是47/49；按钮出来后直接变成49/49」）。

## 2. 根因（读码 + 既有实测，非推测）

| 项 | 事实 | 出处 |
|---|---|---|
| 分母 `totalP` | `Paginator.pageCount(pageStarts)`：按**尺子估算**的内容高切出来的分页表，**比真实可滚范围多算约 1~2 屏** | `Reader.ets:3640`；`03 §J` 实测「显示 34/37 而屏幕已到底 ⇒ 页数按估算多算约 2 屏」 |
| 分子（旧写法） | 滚动模式取「**视口顶部那个字**」落在第几页（`currentOffset()` → `Paginator.pageIndexOf`）⇒ 最后 1~2 页的**页首在真实可滚范围内到不了视口顶部** ⇒ 分子最多只能到 47 | `Reader.ets:3636-3639`、`3411` |
| 触发点 | 2026-10-16 补的「滚到章末直接标成最后一页」在**章末按钮露出那一刻**成立（`curY ≥ endReachY − 8`，`endReachY` = List 报的真实底部）⇒ 47 → 49 **一步跳过去** | `Reader.ets:3647-3651` |

即：**「到底=最后一页」这条规则本身没错，错在它一触发就跨过了那一页** —— 因为分母多算、分子走字符位置，
中间那 1 页（48）在真实可滚范围里根本没有对应的「视口顶部位置」。

## 3. 最小改法（只动 `updatePageLabel()` 的滚动分支）

滚动模式的分子改**按可滚比例映射**页号：

```
lim  = endReachY > 0 ? endReachY : maxScroll      // 真实可滚上界优先，拿不到退回估算
idx  = min(totalP - 1, floor(curY / lim * totalP)) // 比例 ∈ [0,1] ⇒ 每个页号都会被经过
```

- 好处：比例从 0→1 连续变化 ⇒ **页号逐个经过（含 48）**；滚到真实底部时比例 = 1 ⇒ 恰好最后一页。
- `atBottomPx / atBottomList` 那条「到底标最后一页」**保留作兜底**（估算偏大时比例可能只到 48，兜底把它钉到 49）。
- **不动**：分页表（分母）、翻页模式分支、位置锚（位置系统走字符偏移，与页码标签无关）。
- 已知取舍：分母仍按估算（滚动模式的「页」本来就是「屏」的估算）⇒ 页号均匀铺满可滚范围，不再追求「页首严格对齐视口顶部」。

**回退方式**：`cd E:/HuaweiReader && git checkout -- entry/src/main/ets/pages/Reader.ets`
（本轮改动前的备份另存 `release/_bak/Reader.ets.pre-pagelabel.<sha1前8>`）。
