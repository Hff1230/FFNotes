**▍ 1.2 问题现象**

1. 上下滚动模式下，**滚动过程中**进度（章号 / 第 N 页 / 百分比）会异常跳动。
2. 已知历史现象（同族）：退出重进后停在下一章开头；书架显示「续读 0%」；落位收敛到上限被放弃（`position 落位放弃：attempt=41`）；位置游走（`off 4877 → 2765`）。
3. 关键：这些现象**不是"偶发一次"，而是"总是"**（用户口径）⇒ 说明是**结构性**的（每次滚动都在跑的换算路径出了问题），不是边界条件。

**▍ 1.3 根因假设链（按证据强度排序）**

| 编号 | 假设 | 已有证据 | 证据强度 | 若成立的表现 |
|---|---|---|---|---|

**▍ 1.4 复现步骤（供取证任务照此操作）**

1. 打开一本多章的书（建议《凡人修仙传》21.9MB，已有 `.idx`），确认处于**上下滚动**模式。
2. 从第 1 章开始连续向下滚动 **5~10 屏**，跨越至少 1 个章边界。
3. 观察底部状态栏的「章名 / 第 N 页 / 百分比」——是否出现反向跳动或跳一章。
4. 停手等 **10 秒以上**（跨过 8 秒节流），再看一次状态栏数字。
5. 直接回桌面（不划掉进程）→ 重开 App → 进同一本书，看落点。
6. **预期**：位置随滚动单调推进，停手后稳定，重进回到原处。
   **实际**：滚动过程中即出现非单调跳变。

**▍ 1.5 已掌握的证据（来自 03/04 文档原文与实机日志）**

- 落位机制：像素滚动 + 自校准（真实内容高 ÷ 估算内容高 → 把估算像素换成真实像素 → 落位后读回第一块核对，不齐继续收敛）；收敛上限 40。
- 落库时机三条：`onBackground` 心跳立即写；滚动/翻页停稳 ≥8 秒节流写；退出阅读页写并等写完再刷新书架。
- 保存自检三条：① 偏移越出当前章区间 → 丢弃；② 布局未完成（`maxScroll=0`）且未滚动却跳 >1 章 → 丢弃；③ 章号只差 0~1 章、未滚动、进度突变 >25 点 → 丢弃。
- 已知缺口：只拦「跳 >1 章」，跳 1 章漏过。
- 实机日志（04 待办 2）：`restore pos: 按偏移 | idx=1 ch="第一章 山边小村" off=230` → 3 秒后 `save pos: off=4013 ch=2/2448 title="第二章 青牛镇"` → 用户按 home → 再打开 `restore pos: idx=2 off=4013`。
- 目标态（03-B）：正文不许整本常驻，改成「当前章 ±3 章窗口从磁盘读」，sidecar 补每章字节区间；PSS 148MB → 目标 ≤40MB。

**■ 二、修复方案**

**▍ 2.1 方案对比**

| 维度 | 方案A：换位置来源（内容→内容） | 方案B：只修保存护栏 | 方案C：回到 `scrollToIndex` 精确跳转 |
|---|---|---|---|
| 做法 | 用官方可见项回调/查询接口直接拿「当前可见首项」→ 由**项索引映射到章与字符偏移**，不再由像素比例反推 | 保留现有像素数学，只把保存自检补严（跳 1 章也拦、无交互不写、落位期禁存） | 用 `childrenMainSize` 提供精确块尺寸 + `scrollToIndex` 落位，放弃像素自校准 |
| 治什么 | **治本：滚动中的跳动消失**（位置不再由估算像素推导） | 只保"不写坏库"，用户看到的跳动**仍在** | 治本（落位一次到位），但要求块尺寸**精确** |
| 风险 | 中（要建立 项索引↔偏移 映射，影响落位/书签/听书） | **低** | 中高（尺寸不精确会引入新偏差：滚动条跳动、总高偏差） |
| 工作量 | 中 | 小 | 中 |
| 依赖 | 官方 API 均可用（见 2.4 版本核对） | 无 | 块高需与渲染同源（E-5） |

**▍ 2.2 推荐方案**

**A（治本）＋ B（保底）并行上线**，C 作为 A 的"精度增强"放到 A 稳定之后再评估：

1. **B 先上**（无依赖、低风险、可独立回滚）：先把"异常值不许写库"这条红线守住 —— 这是用户的**第一条红线**，优先级高于任何观感问题。
2. **A 跟上**（治本）：位置来源从"像素估算"换成"可见项索引"，从结构上消除滚动中的跳动。
3. **C 按需**：若 A 上线后落位仍不够"一次到位"，再补 `childrenMainSize`（它同时让 `currentOffset` 与内置滚动条变准，见 2.4 来源①原文）。

> **2026-10-14 变更**：原先"不改成按章切换"的约束**已被用户决定推翻** —— 上下滚动**确定改为按章切换**（章节不同时上屏；章末显示「下一章」、章首显示「上一章」按钮，见 [[04-纯阅待办与验收]] 五、5.2）。本项改造独立立为 **FIX-005**，并带来两个后果：
> - **好消息**：单章视图下章号不再需要从像素/跨章高度推出，**FIX-002 的映射大幅简化**（只需"章内块索引 → 章内偏移"，章号由"当前章"状态直接给出）；RC-1 的跨章漂移路径基本消失。
> - **坏消息**：章**内**位置仍依赖像素估算，**章内百分比仍可能小幅跳动**；且 FIX-001 的护栏**依然必须做**（异常态照样可能被写库）。
> - **顺序硬约束**：**FIX-005 必须排在 FIX-000 之后** —— 先在旧行为下取到基线日志，否则"跨章跳动"现象变形，取证失去参照。

**▍ 2.3 技术实现**

**▍ 2.3.1 为什么"像素估算"必然漂移（官方机制，不是猜测）**

官方原文（List 组件 `initialIndex` 说明）：

> 设置了 initialIndex 后，List 从 initialIndex 对应的子组件开始布局，**在这之前的子组件未参与布局，无法计算准确大小**，因此通过 currentOffset 接口获取到的 List 的滚动总偏移量**通过估算得出，可能会有误差**。可通过设置 childrenMainSize 确保 List 的滚动总偏移量的准确性。

而在子组件主轴尺寸不一致时，官方对 `childrenMainSize` 的说明是：

> 该属性通过向 List 组件提供所有子组件在主轴方向的大小信息，确保在面对**子组件主轴尺寸不一致**、增删子组件、使用 scrollToIndex 等场景时，List 组件能够**维护其滑动位置准确性**。这样，scrollTo 可以准确的跳转到指定位置，**currentOffset 可以获取到当前准确的滑动位置**，内置滚动条可以实现**平滑移动无跳变**。

**推论**：在未提供 `childrenMainSize` 的变高列表里，`currentOffset` / 总内容高本身就是**估算值**；滚动过程中块被逐个测量，估算值持续修正 ⇒ 用它做分母的「自校准比例」必然持续变化 ⇒ **推出的内容位置/章号非单调**。这与用户口径「总是异常跳动」完全吻合。

**▍ 2.3.2 主修（方案 A）：位置来源改为「可见项索引」**

思路：**不要再从像素推内容，而是问组件"现在哪个子组件可见"**，再把这个索引映射成（章号, 字符偏移）。

可用的官方接口（全部 ≤ 目标 SDK 的 API 26，无需版本门槛）：

| 用途 | 接口 | 起始版本 | 关键点 |
|---|---|---|---|
| 拿"可见首/末项索引"的变化 | `onScrollVisibleContentChange` | API 12+ | 「有子组件划入或划出 List 显示区域时触发」，**列表初始化时也会触发一次**；显示区域第一个/最后一个子组件索引变化时触发 |
| 按坐标反查是哪个子组件 | `getVisibleListContentInfo(x, y)` | API 14+ | 入参基准点是 **List 组件的位置**；返回 `index` / `itemGroupArea` / `itemIndexInGroup`；都不在范围内时 `index = -1` |
| 上方增删数据时保持可见位置不变 | `maintainVisibleContentPosition(true)` | API 12+ | 仅对 **LazyForEach 在显示区域外增删**有效（抓取补章/换源场景相关） |

**映射链（必须建起来，这是本方案的实现核心）**：

```
可见项 index（List 内位置）
   → 列表项 = 某章的第 k 块（需要"块索引 → 章 + 章内块序号"的映射表）
      → 章起始字符偏移 + 卡内前序块累计字符数
         → 全书字符偏移 offset（＝现有位置锚三件套的权威值）
```

落地要求：
- 映射表在分章/切块时随 `.idx` sidecar 一起产出（每块记录：章号、块内起始字符偏移、累计块序号）；
- **`offset` 仍是唯一权威**，可见项索引只是"观测手段"，不许直接当进度写库；
- `.idx` 失效重扫（补章/换源后）→ 映射表重建后必须**按 `offset` 重新落位**，不许沿用旧索引；
- 滚动停止时的 `offset` 取"当前可见首块"的偏移，而不是像素换算值。

**前提约束（官方明令，必须遵守）**：

> 提供的主轴方向大小信息**必须与子组件实际在主轴方向的大小一致**，子组件在主轴方向大小变化或者增删子组件时**都必须通过 ChildrenMainSize 对象方法通知**。

⇒ 所以块高**必须与渲染同源**。若现有块高是"估算值"（E-5 待确认），先不要急着接 `childrenMainSize`，否则会把"位置漂移"换成"总高偏差 / 滚动条跳动"。同源算法可用 `@kit.ArkGraphics2D` 的 `Paragraph`（`layout()` + `getLineMetrics()`）算文本实际行高——这与渲染引擎同一套度量。

**▍ 2.3.4 护栏（方案 B）：保存自检四闸**

> 口径正文在 [[03-纯阅关键约定与踩坑]] **A-4**（唯一来源），本节只写实现落点，**不重述口径**。
> 2026-10-14 复核已定两条必要修法（见 `docs/review/2026-10-14-口径复核与处置.md` P0-1 / P0-2），实施时必须一起做：

| 闸 | 条件 | 动作 |
|---|---|---|
| G1 | 自打开以来**无任何用户交互**（`userTouched=false`） | `saveProgress()` 直接 return，只写日志 |
| G1-例外 | **TTS 播放中**（`ttsPlaying == true`）视为"已交互" | **不予拦截**，听书自动推进/自动跨章照常落库；仍走 G3/G4 |
| G2 | 无用户交互期间 | **不许因滚动推导改 `curIndex`**（只有真人滚过/翻过才认） |
| G3 | `!userScrolled` 且 **jumped ≥ 1** 且偏移 ≈ 新章开头（`off == ch.start`） | 判伪值丢弃（把现有"只拦 >1 章"改成"≥1 章"） |
| G3-白名单 | 位置变化**源于**：切章按钮点按、目录/书签/进度条跳转、听书自动跨章 | **不算伪值**，正常写库（否则 FIX-005 的"切章回到新章开头"会被自己拦掉） |
| G4 | `placing` 期间（落位未收敛） | 禁止写库；退出时若仍在 `placing`，按"最后一次已确认的 `offset`"写 |

同时：**收敛上限从 40 降到 3~4 次**并启用估算兜底（03-C 已给出建议），避免 1~2 秒白卡期间状态被改写。

**▍ 2.5 风险评估**

**影响范围**
- 直接影响：阅读页的位置推导、落位、保存；`.idx` sidecar 的产出格式（新增块索引表）。
- 间接影响：书签跳转、目录跳转、听书自动翻页/高亮（都依赖 `offset`）、书架百分比与「续读 N%」。
- 不受影响：装载与编码（BookLoader/TextUtil）、书源子系统、备份导出、分页（Paginator，只在左右翻页模式用）。

**副作用分析**
- 若块索引表与数据源索引**不一致**（例如 LazyForEach 键不稳定、跨章块混排时索引错位）→ 位置会**系统性偏移**（不是跳动，是慢性错位）。因此 E-4 必须查清；`keyGenerator` 禁止 `stringify`。
- `childrenMainSize` 若尺寸不准 → 换成"总高偏差/滚动条跳动"。**故 C 排在 A 稳定之后**。
- 位置来源切换期间，新旧两条路径并存 ⇒ 必须有开关且默认单一路径生效，避免一帧内两个来源互相覆盖。

**回滚方案**
- 改码前备份 `Reader.ets`（及被改的 `*.ets`）到工程内 `.bak-<时间戳>/`；
- 按 FIX 粒度独立提交，每一步可单独 `git revert`；
- 新旧位置来源用编译期/设置项开关切换，出问题一键回旧路径；
- 回滚后必须**保留护栏（B）**：即使位置来源回到旧路径，也不许再写坏库。

**□ FIX-000 取证：确认根因链（阻断闸）**

- 任务ID：FIX-000　级别：**P0（阻断）**　影响模块：阅读页日志 / 调试　依赖：无　风险：低
- **问题描述**：用户报「上下滚动进度总是异常跳动」，现有假设链（RC-1~RC-4）尚未有决定性证据，无法确定该改哪条路径。
- **修复方案**：不改逻辑，只**加临时探针日志 + 取证**。
- **输入**：工程 `E:\HuaweiReader`；真机 Pura 70 Pro（hdc over WiFi，见 [[02-纯阅工程与架构]] §5）；症状复现步骤见 1.4。
- **输出**：
  - 探针日志（E-2）：估算内容高 / 真实内容高 / 比例 / 推出 `offset` / 推出 `curIndex` / `userScrolled` / `placing`；
  - 完整 `hilog -x -T reader` 片段（E-1）；
  - 代码检索结论（E-3/E-4/E-5）；
  - **结论表**：RC-1~RC-4 逐条「成立 / 不成立 / 无法判定」+ 决定性时序说明。
- **执行步骤**：① 备份 `Reader.ets`；② 在换算处与保存处加临时日志（仅日志）；③ 装真机并 **force-stop 后重启**（只 install 不重启跑的是旧进程）；④ 按 1.4 复现并抓日志；⑤ 提交结论表 + 日志原文；⑥ **摘掉临时探针**（或标记为调试开关）。
- **验收标准（不含测试）**：
  - [ ] RC-1~RC-4 每条都有明确判定与对应日志行
  - [ ] 给出"跳变发生在落位收敛期间还是停手 8 秒后"的时序结论
  - [ ] 可编译通过、无新增告警；临时探针已摘除或收敛为开关

**□ FIX-001 保存护栏：四闸 + 收敛上限下调**

- 任务ID：FIX-001　级别：**P0**　影响模块：进度保存自检、落位　依赖：RC-2 成立即可（不依赖 FIX-000）　风险：**低**
- **问题描述**：自检只拦「跳 >1 章」，跳 1 章放行；落位期间与无交互期间都可能写出伪位置。

- **输入**：`Reader.ets`（`saveProgress` / 自检 / 落位收敛三段职责）；口径见 [[03-纯阅关键约定与踩坑]] A。
- **输出**：修改后的 `Reader.ets` + 修复说明（改动点与理由）。
- **执行步骤**：① 备份；② 实现四闸；③ 下调收敛上限；④ 自检日志保留可读原因（`保存进度被拦：原因`）；⑤ 提交并附改动说明。

  - [ ] 四闸全部实现，跳 **1** 章也拦

**□ FIX-005 上下滚动改「按章切换」（架构改造）**

- 任务ID：FIX-005　级别：**P0**　影响模块：阅读页滚动视图、落位、听书跨章　依赖：**FIX-000（取基线后才动）**　风险：中
- **问题描述**：现行上下滚动是「无缝窗口、多章连排」，与 2026-10-14 定案的新规格（章节不同时上屏）不符；且多章连排要求跨章的高度估算与落位自校准，是进度跳动的放大器。
- **修复方案**：按 [[01-纯阅功能规格]] §2.1 改造：① 同一时间只渲染当前章；② 章末滚到底显示「下一章」按钮、章首显示「上一章」按钮，**点按才切**；③ 切章后位置重置到新章开头，点「上一章」停在上一章**末尾**；④ 首章不显示「上一章」、末章不显示「下一章」；⑤ 听书跨章仍自动推进。
- **输入**：`Reader.ets`（滚动视图 + 章状态 + 落位）；`01-纯阅功能规格` §2.1（规格）；`03-C`（落位自校准的改造代价）。
- **输出**：改造后的 `Reader.ets` + 修复说明（含「自校准作用域缩小到单章」的改动点）。
- **执行步骤**：① 备份；② 单章视图改造；③ 加章末/章首过渡按钮与显隐边界（首/末章、短章不足一屏时两个按钮可同时可见）；④ 切章后重新落位（配合 `placing` 禁存）；⑤ 听书跨章路径回归；⑥ 提交 + 说明。
- **验收标准（不含测试）**：
  - [ ] 屏幕上任何时刻只有一个章的内容
  - [ ] 章末出现「下一章」、章首出现「上一章」；首/末章对应按钮不出现
  - [ ] 切章后位置正确（下一章→开头；上一章→末尾）
  - [ ] 听书自动跨章仍工作
  - [ ] 可编译通过、无新增告警

**□ FIX-002 位置来源改为「可见项索引」（治本 · 按单章视图简化）**

- 任务ID：FIX-002　级别：**P0**　影响模块：滚动位置推导、`.idx` sidecar、落位　依赖：**FIX-000**　风险：中
- **问题描述**：位置由"像素 × 自校准比例"推导，比例随滚动持续变化 ⇒ 进度非单调跳动（RC-1）。
- **修复方案**：按 2.3.2 建立「可见项索引 → 章 + 字符偏移」映射；用 `onScrollVisibleContentChange`（必要时 `getVisibleListContentInfo` 校正）取可见首项；`currentOffset` 比例换算降级为**兜底/校验**，不再作为唯一来源。
- **输入**：`Reader.ets`（滚动处理 + 位置推导 + 落位）；`TextUtil.ets`（分章/切块，产出块索引表）；`.idx` sidecar 格式；`ChapterDataSource.ets`。
- **输出**：修改后的 `Reader.ets` / `TextUtil.ets`（或新增块索引模块）+ 修复说明；`.idx` 新增块索引表的格式说明。
- **执行步骤**：① 备份；② 定义块索引表（章号 / 块内起始字符偏移 / 累计序号）并与 `.idx` 一起产出；③ 接入可见项回调，建立映射；④ 旧像素路径保留为开关/校验；⑤ `.idx` 重扫后按 `offset` 重新落位；⑥ 提交 + 说明。
- **验收标准（不含测试）**：
  - [ ] 位置来源为可见项索引，`offset` 仍为唯一权威
  - [ ] 旧像素路径降级为兜底（或开关），不存在两来源同帧互相覆盖
  - [ ] `.idx` 重建路径已按 `offset` 重新落位
  - [ ] 可编译通过、无新增告警

**□ FIX-003 `childrenMainSize` 精度增强 + 自校准瘦身**

- 任务ID：FIX-003　级别：P1　影响模块：滚动定位精度、滚动条　依赖：FIX-002　风险：中
- **问题描述**：即使位置来源改好，`currentOffset` 与内置滚动条仍基于估算总高；落位可能要多次收敛。
- **修复方案**：按 2.3.3 接入 `childrenMainSize`（尺寸必须与渲染同源）；随 A 稳定后**删除**像素比例换算的残留。
- **输入**：`listChildrenSize`：与渲染同源的块高（`Paragraph.layout()` + `getLineMetrics()`）；`List` 的数据源结构。
- **输出**：修改后的 `Reader.ets` + 尺寸计算模块 + 修复说明。
- **执行步骤**：① 备份；② 实现与渲染同源的块高计算；③ `childrenMainSize` 绑定 + `splice/update` 维护（增删块、改字号、改行距时同步通知）；④ 观察确认无"总高偏差/滚动条跳动"；⑤ 删除自校准残留；⑥ 提交 + 说明。
- **验收标准（不含测试）**：
  - [ ] 块高与渲染同源；改字号/行距后尺寸同步通知
  - [ ] 自校准比例路径已删除（或明确标注为不可达）
  - [ ] 可编译通过、无新增告警
