**■ 纯阅 · 验证测试策略初稿：上下滚动进度异常跳动**

> 文档性质：**初稿**，用于后续生成详细测试文档。测试项通过「对应 FIX 任务 / 受影响模块」与 `fix-plan.md` 建立关联，不复制修复内容。
> 纯阅的验收一贯要求**判据 + 日志原文**（不接受"看起来好了"），本策略沿用该口径：凡判据只写"看日志哪一行 / 看界面哪个数字"。

**▍ 1.2 功能点清单**

- [ ] 上下滚动时「章名 / 第 N 页 / 百分比」**单调推进**，无反向跳动、无跳章
- [ ] 停手后位置**稳定**（跨过 8 秒节流落库不再变）
- [ ] 退出重进 / 后台切回 / 杀进程重进，**回到原处**（误差 ≤1 屏）
- [ ] 跳 **1 章**的伪位置被拦（不再被写库）
- [ ] 落位收敛次数降到 **3~4 次**以内，不再出现 `attempt=41` 放弃
- [ ] 书签 / 目录跳转 / 听书自动翻页**仍准**（`offset` 权威性未被破坏）
- [ ] `.idx` 重扫（抓取补章/换源）后，位置**按 `offset` 重新落位**，索引不错位

**▍ 2.3 回归测试**

**回归范围**

- 核心功能：上下滚动阅读、左右翻页阅读（纸张效果接线后）、目录/书签跳转、位置锚三件套恢复（章名优先）
- 关联功能：听书（逐段高亮、自动翻页/滚动、切章接续）、书架进度显示与「续读」、文件夹/分享/备份到文档、说明书
- 不受影响但需冒烟：书源（搜索/目录/正文）、装载与编码嗅探、导出

**▍ 2.4 场景测试（模拟真实使用）**

| 场景 | 操作步骤 | 预期结果 |
|---|---|---|
| 场景1 长距阅读 | 上下滚动模式连续滚 5 分钟，每章点「下一章」跨 ≥5 章 | 位置单调；无跳动；无跨章连排；帧率稳定 |
| 场景2 中断恢复 | 滚动到第 8 章 → 回桌面 → 划掉进程 → 重开进书 | 回到第 8 章同位置（误差 ≤1 屏） |
| 场景3 听书联动 | 滚动模式下开听书，让它自动推进跨 2 章 | 朗读段与高亮一致；位置单调前进；**跨章由听书自动完成**（不依赖按钮） |
| 场景4 「从头读」 | 从头读 → 立刻退出 → 重进 | 停在书首（不被旧进度覆盖） |
| 场景5 大书首装 | 打开 37MB 未建索引的书，装完立刻滚动 | 装完可滚；位置不跳；内存观察项见 4.2 |

**■ 四、测试建议**

**▍ 4.1 扩展方向（建议在详细测试文档中展开）**

1. **测试数据准备**：21.9MB 有 `.idx` 的《凡人修仙传》、37MB 首装的《剑来》；另需一本**极不规整**的 txt（章节标题混乱、含大量空行/硬换行）用于映射健壮性；一本**单章几百万字**（触发 `MAX_CHAPTER_CHARS`）的书。
2. **真机日志判据固化**：把 `hilog -x -T reader` 的关键行（`loaded … chars/chapters`、`save pos:`、`place blk|place fix|place done`、`保存进度被拦：原因`）整理成"一行一判据"的对照表，供后续自动化解析。
3. **可自动化的部分**：UT-001~UT-005（纯逻辑）可完全自动化；V-003/V-004 可通过日志解析半自动化。
4. **性能测试**：滚动帧率曲线（Profiler）+ 滚动 5 分钟后的内存曲线；基准取修复前的同机同书数据。
5. **边界与异常**：`.idx` 损坏/缺失、书文件被追加后索引失效、坐标落在子组件之间（`getVisibleListContentInfo` 返回 `index = -1`）、快速甩动与慢速拖动的差异。

**▍ 4.2 注意事项**

- **装完必须重启 App**（`aa force-stop` 或从最近任务划掉）——只 `install` 跑的还是旧进程，会出现"以为修好了其实点了旧代码"。
- **判断必须以日志原文为准**，不要凭"看起来不跳了"下结论；跳变如果是**幅度小**而不是消失，滚动中不一定肉眼可见，必须看日志。
- 内存指标不要混进本问题：`148MB → ≤40MB` 属于**待办 3（正文不许整本常驻）**，本问题的通过条件不含它。
- 修复期间新增的**临时探针日志**（FIX-000）在验收后必须摘除或收敛为开关，避免污染长期日志判据。
