## 一、测试范围

### 1.1 受影响模块

| 模块 | 关系 | 优先级 |
|---|---|---|
| 判别层：合成路径（内置 `speakBuiltinCurrent` / 系统 `eng.speak`） | 决定走哪条分支 | **高** |
| 内置引擎配置（`BuiltinTtsWorker.ets:29-41`：`lexicon`、`ruleFsts`、`numThreads`） | A 分支目标 | 高 |
| 语速参数（`BookSpeaker.speed`、`setParams` BS:1088） | A-① 目标 | 高 |
| 送引擎前文本清洗（新增纯函数） | C 分支目标 | 中 |
| `split` 切点 | **不改**（仅回归保护：段数/maxLen 不得变） | 中（回归） |
| 音频写队列（`pcmPending`/`drop tail`/`uf`） | B 分支（已有方案） | 中 |

### 1.2 功能点清单

- [ ] 判别实验能落到唯一一支（A / B / C）
- [ ] PCM 层与播放层能二分（同一句：PCM 里破 vs 播出来破）
- [ ] A-① 语速下调后同句不再破，且整体听感不「拖沓」
- [ ] A-③ 追加词条后该词整体念（不被拆）
- [ ] C-① 清洗后零宽字符/全角空格不再造成断词，且原文与 start/end 不变
- [ ] 切点/段数零变化（回归）
- [ ] 用户亲口「不再读破」

## 二、测试类型

### 2.1 判别测试（零改码，人工）

| 编号 | 场景 | 判读 |
|---|---|---|
| DT-000 | 复制那句原文（含前后 5~10 字）看「说 / 一」之间有没有空格或不可见字符 | 有 ⇒ **C（首选，一眼可定）** |
| DT-001 | 系统音色听同句 | 不破 ⇒ A（内置模型独有）；**所有中文音色都一样 ⇒ A 排除，直接走 C** |
| DT-002 | 语速 0.8 听同句 | 清楚 ⇒ A'（速度/模型过载） |
| DT-003 | 同句连听三遍 | 破位随机 ⇒ B（供给）；固定 ⇒ C（文本/词库） |
| DT-004 | 该句单独成短章 | 仍破 ⇒ C |
| DT-005 | `silenceScale` 0.2→0.05 后听同一句（内置分支；单变量包） | 立刻连上 ⇒ 引擎内部把它切成两句 + 句间静音，定性完成；无变化 ⇒ 走语速/模型 |

### 2.2 单元测试（离线，跑生产 `.ets`）

| 测试项 | 内容 | 优先级 |
|---|---|---|
| UT-000 | **汉字之间的半角/全角空格在「送引擎副本」里被抹掉**（原文、`start/end`、`seg.text` 的可逆性断言全不变） | **最高** |
| UT-001 | 文本清洗纯函数：抹 `\u200b\u200c\u200d\u200e\u200f\u00ad\u2060`、`\u3000`，其他字符不动 | 高 |
| UT-002 | 清洗可逆性：`strip(clean(t)) === strip(t)`（除被抹字符外逐字相同） | **高** |
| UT-003 | 语速计算：内置分支 `speed*dialogBoost` 边界（0.5~2.0 夹取） | 中 |
| UT-004 | `split` 回归：同输入段数/`maxLen`/`avgLen` 与改前**逐字相同** | **高** |
| UT-005 | `SpeechSeg.start/end` 不变（黄金样本逐段比对） | **高** |

**边界**：代理对（emoji/扩展 B 汉字）、全角空格连续多个、零宽字符在词首/词尾。

### 2.3 集成测试

| 编号 | 场景 | 判据 |
|---|---|---|
| IT-001 | 内置分支整段播放：`seg` 行 `engine=builtin`、`stockMin/uf` 正常 | 无新增欠载 |
| IT-002 | PCM 导出（`PCMDUMP_ON`）后回放：PCM 与听到的一致 | 二分结论成立 |
| IT-003 | 语速下调后：段时长 `dur` 同比例变长、跟读节拍不乱（`scrollcmd` 去重集不新增源） | 跟读仍正常 |

### 2.4 回归测试

- `剑来` 样本（`scratch/drop4/seg_dump.txt`，1193 段）：段数/maxLen 不变；段尾分布不变。
- 高亮：`hi` 日志 `inScreen` 比例不下降；截图复核一次。
- 预取：`pfxdone→pfx take` 提前量中位仍 ≥1s。

### 2.5 场景测试（真机，听感由用户判）

| 场景 | 操作 | 预期 |
|---|---|---|
| 1 | 用户的书 + 内置音色，听 3 分钟 | 词不再被读破 |
| 2 | 同上，系统音色 | 不变（回归） |

## 三、验收标准

### 3.1 必须通过

- [ ] 判别结论明确落到 A/B/C 一支（有依据，非猜测）
- [ ] 用户亲口「不再读破」（唯一有效听感判据）
- [ ] 切点/段数/`maxLen` 零变化（未动 `split`）
- [ ] `SpeechSeg.start/end` 逐字节不变
- [ ] 离线门禁现码全绿 + `git show HEAD:` 旧码**报红**
- [ ] 原文 SHA256 不变（本地书）

### 3.2 建议通过

- [ ] PCM 导出证据留存（同句 PCM 与播放结论一致）
- [ ] 语速下调后用户不觉得「太慢」
- [ ] 追加词条后 `lexicon` 加载时间无明显上升

### 3.3 验证点清单

| 编号 | 验证点 | 方法 | 通过标准 |
|---|---|---|---|
| V-001 | 分支判定 | §2.1 四问 | 结论唯一 |
| V-002 | PCM 二分 | `PCMDUMP_ON` 回放 | 能说清破在哪一层 |
| V-003 | 切点未动 | `seg_dump` 黄金样本 | 逐段相同 |

| V-005 | 门禁有牙 | 旧码跑同一用例 | 报红 |

## 四、测试建议

### 4.1 扩展方向（后续详细文档展开）

1. **测试数据**：被读破的原始句子（用户提供 3~5 句）、`剑来` 黄金段表、内置/系统两条路径同句对拍。
2. **自动化**：UT-001/002/004/005 可离线；IT 需模拟器。
3. **性能**：追加 lexicon 后引擎首载时间（现 1.6s）与内存（现 PSS 328MB）对比；语速下调不改性能。
4. **安全**：不涉及。

### 4.2 注意事项

- ❗**量具先自证**：`PCMDUMP_ON` 是默认关的只读导出，先拿一个**已知会破**的句子确认导出的 PCM 真能听出破，再拿它判 A/C 与 B。
- ❗**一次只动一个变量**：语速、模型、词条、清洗不要同一包上；否则日志与听感都分不清是哪条起作用。
- ❗**技术指标不等于听感**：`uf=0`、段尾 100% 标点、`maxLen` 正常都不能证明「不读破」；只认用户那句「好了」。
- ❗**AB 前先证明改前是红的**：旧包必须能复现破，否则样本不成立。
- ❗**别用切点指标冒充结论**：第 1 版曾把「段尾非标点占比」当验收线，本案已作废（切点本来就在标点上）。
