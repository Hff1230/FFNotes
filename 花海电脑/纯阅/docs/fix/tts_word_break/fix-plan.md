### 1.2 问题描述

听书时一个词被「读破」：听感上词被拆开、连不起来，或字音被截断；但**文本是干净的**（已按标点切好，段也落在标点上）。

### 1.3 已核实的事实与已排除的原因

#### 事实 1：我们的切句里**没有**「句子内部再切」的规则（代码核实）

- 唯一分段器 `BookSpeaker.split`（BS:862-919），切点判据只有一条（BS:902-903）：
  `isCloseQuote || isNl || bufLen >= cap || isEnder || isComma || (isSoft && bufLen >= SOFT_MIN)`
- **一段 = 一次合成**：内置 `speakBuiltinCurrent` → `BuiltinTts.synthesize(seg.text)`（BS:797）；系统 `eng.speak(seg.text)`（BS:1356，预取 1425）。**没有任何代码把 `seg.text` 再切小**。
- 引擎内部另有 `maxNumSentences = 1`、`silenceScale = 0.2`（`oh_modules/.ohpm/sherpa_onnx@1.13.3/oh_modules/sherpa_onnx/src/main/ets/components/NonStreamingTts.ets:103-104`）—— 它只按**标点**决定句子，不会在词中间开刀。

#### 事实 1b：用户给的实例复算（2026-10-19，等级：高）

用户实例：「会拍着胸脯说**一句**」——听感在「说」与「一」之间顿一下。

把该句连同上下文喂给 `split` 的现行规则复刻（同一套字符集/阈值）：

```
输入：他这人就爱面子，会拍着胸脯说一句，包在我身上，转身却把事情忘到脑后。
seg0 [0,8)   '他这人就爱面子，'
seg1 [8,17)  '会拍着胸脯说一句，'      ← 说/一 在同一段内
seg2 [17,23) '包在我身上，'
seg3 [23,34) '转身却把事情忘到脑后。'
```

⇒ **切句不会在「说」和「一」之间断开**；这个停顿发生在**同一次合成、同一个段**的内部 ⇒ 只剩「合成侧（PCM 里就有）」和「播放侧（PCM 没有、播放时欠载）」两种可能。

⇒ **结论**：「词被读破」不可能由我们的切句产生（除非触发事实 3 的强制切分，而真实样本里从未发生）。

#### 事实 1c：用户确认「这句本身没换行」（2026-10-19）

⇒ 该句就是**一个段、一次合成**，段内停顿。再叠加既有真机实测：**欠载（`uf>0`）100% 落在段末**（`ufAt ≥ dur`，最小 769 ms，见 `docs/fix/tts_drop_stutter/M-001`）⇒ **也不是我们灌数造成的**。

⇒ 唯一剩下的层是**引擎合成**：它自己在这两个词之间插了停顿。可动的引擎旋钮有三个（都在 `BuiltinTtsWorker.ets:30-41` 的 `OfflineTtsConfig` 或 `TtsGenerationConfig`）：
1. **`silenceScale`**（现值 = 默认 **0.2**，代码里从未设过）——引擎在自己断出的「句」之间插静音，若它把「说 / 一句」切成两句，这段静音就正好落在这里；
2. **`speed`**（内置按 `BookSpeaker.speed` 传）；
3. **模型**（`matcha-icefall-zh-baker`，社区小模型，动宾边界容易插停顿）。



#### 事实 2：真实样本切点全落在标点上（实测，等级：高）

| 样本 | 规模 | 结论 |
|---|---|---|
| `scratch/drop4/seg_dump.txt`（《剑来》ch384 真机落盘） | 1193 段 | 段尾：`，`884 / `。`112 / `”`90 / `：`72 / `？`19 / `！`9 / `…`4 / **非标点仅 2 段**（章节标题、破折号）；`maxLen=25` ≪ `SEG_MAX=90` |
| 全量 412 条 `chapter segs=` 样本（Hermes scratch，99 个文件） | — | `maxLen` min 19 / **中位 23** / max 37 ⇒ **90 字硬上限从未触发** |

⇒ 与你的判断一致：标点/换行/硬上限都不是元凶（硬上限只在「无标点长串 / 英文段落」触发，那是另一类书的另一类问题）。

#### 事实 3：内置引擎词库其实很全（实测，等级：高）

`resources/rawfile/models/matcha-icefall-zh-baker/lexicon.txt`：**66,375 行**，命中样例：

```
30454:厚度 hou4 du4       62885:银行 yin2 hang2
63096:长大 zhang3 da4     62398:重读 zhong2 du2
```

⇒「词不在库就按单字读」只对**专有名词 / 新词 / 生僻词**成立，常见词与常见多音词都已收录 —— 解释不了「普通词被读破」，只能当待验项。

#### 已排除 / 降级（第 1 版主因，现作废）

| 旧假设 | 现状 | 依据 |
|---|---|---|
| H1 排版换行被当一级断点 | **排除（对本问题）** | 你已按标点切好正文；真实样本 `maxLen` 中位 23、段尾 99.8% 落在标点 |
| H2 90 字硬上限强切 | **低概率（条件项保留）** | 同上；仅无标点长串 / 英文段落触发 |
| H3 正文夹不可见字符（U+200B / U+00AD / 全角空格转半角） | **低概率（实测）** | 扫样本：`seg_dump` 汉字间夹分隔符仅 **2 处**、`test_book.txt` **4 处**，全在「第X章 标题」里。注：`TextUtil.CTRL_RE`（TextUtil.ets:47）确实**不清** `\u200b/\u00ad/\u200c/\u200d/\u200e/\u200f`，`\u3000` 会被换成半角空格（:215）⇒ 留作兜底，非本案主因 |

#### 事实 1d：**所有中文音色都一样**（2026-10-19 用户追加）⇒ 跨引擎

内置（sherpa `matcha-icefall-zh-baker`）与系统（华为 Core Speech Kit 聆小珊等）是**两套完全不同的引擎**，它们在同一处顿一下，说明**共因不在模型**，只能是两条：

| 共因 | 能否解释「位置固定 + 与标点无关」 | 说明 |
|---|---|---|
| **送进去的文本里，这两个字之间有一个空格或不可见字符** | ✅ 能（所有引擎都把空格当词语/句子边界） | 尤其可疑：`TextUtil.normalize` 会把 **全角空格 `\u3000` 换成半角空格**（TextUtil.ets:215），而 `split` **不把空格当断点**（切点只看标点/换行/上限）⇒ 段文本里就带着「说 一句」，一次合成、中间却是引擎眼里的词边界 |
| **播放侧断供**（20ms 渲染缓冲见底） | ⚠️ 半能（与音色无关，但位置应随机） | 若每次顿在同一处则不像它 |

⇒ **主假设改为 C 支（文本层）**；引擎模型假设（A）**已被这条口径排除**（不可能几个不同引擎同一个毛病）。

## 二、修复方案（按分支，互斥，不要一起上）

> **排序（2026-10-19 按「所有中文音色都一样」修订）**：**首选 C-①**（文本层清洗 —— 跨引擎唯一共因）；B 支只在「顿的位置随机」时才查；A 支（silenceScale / 语速 / 换模型）**降为条件项**，仅当「只有某一个音色出问题」时才用。

### A. 条件项：单个音色才出问题（内置独有 / 某个音色独有）

| 顺序 | 手段 | 代价 | 判据 |
|---|---|---|---|
| **A-⓪** | **`silenceScale` 0.2 → 0.05/0**：引擎在自己断出的「句」之间插静音，代码里从没设过（`BuiltinTtsWorker.ets:30-41` / `TtsGenerationConfig.silenceScale`）。**它同时是判据**——调到 0 该句立刻连上 ⇒ 证明引擎把「说 / 一句」切成两句 | 1 个配置值 + 开关 | 该句立刻连上 ⇒ 有效且定性完成；无变化 ⇒ A-① |
| A-① | **默认语速下调**（1.00 → 0.92~0.95，仅内置分支） | 1 个常量 + 开关 | 慢速清楚 ⇒ 有效；仍破 ⇒ A-② |
| A-② | **换内置中文模型**（现 `matcha-icefall-zh-baker`，NCC 仅自用版）：体积/授权逐项评估，**先证质量再换** | 新模型 40~90MB，`fetch_tts_model.py` + sha256 + 授权核对 | 用户盲听 A/B（同句 3 段）选优 |
