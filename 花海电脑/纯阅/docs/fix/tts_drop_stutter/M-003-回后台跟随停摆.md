# M-003 退到后台 → 回前台后跟随停摆、高亮留在屏外

> 用户 2026-10-18 问「为什么真机现在的听书没有高亮」。
> 数据：`spike_ab2/b.txt`（tts_b 口径）与 `spike_ab2/diag.txt`（tts_diag 口径），同一次 spike 会话。
> 结论：**高亮一直在更新，是视图没滚过去**；故障起点不是换章，而是 **12:34:21.729 App 退到后台**（`app-bg`），比换章（12:35:02.147）早 41 秒。

## 二、根因链（三步）

1. **后台期间 ArkUI 不布局** ⇒ `scrollTo` 全部变成空操作（`chapter-pin got=12083`、`scrollsettle over=12083`，同时段 `pos` 一条不涨、换章后 `blkbuild` 也是 0 条）。这解释了「换章归零也无效」——不是夹取，是 List 根本没动。
2. `currentOffset()` 因此冻结在旧章 12083；`followFloor` 的抬升逻辑**只凭 `currentY()`**（`Reader.ets:1401-1410`）⇒ `floor-raise 0->12083`，把「旧坐标」当成「List 自己向前漂了」。
3. 之后每拍目标 0 < 地板 12083 ⇒ `no-back`（`Reader.ets:1411-1414`）直接 return，**连定位令都不再发**；而该行的 `followNote` 被同一次调用里先出现的 `est-fallback` 占掉了 1 秒节流（`Reader.ets:1158`），所以日志里查不到（全日志 `no-back` = 0），只有 `center|` 归零这一个现象。

⇒ 只有「回前台 + 有人重摆」才能解开；日志证据止于 12:36:30，回前台后恢复的过程在设备侧（12:37:45 的 `pos y=0`）。

## 四、修法建议（按优先级；每条都有回退方式）

1. **地板只认「真的动过」才抬**（改 1401）：要求这一拍收到过新的 `onScroll`（或 `y` 相对上次真的变过）才允许抬地板。回退：去掉该前置条件。
   验收：换章后不再出现 `floor-raise 0-><旧章大值>`；`seg|…floor=` 在换章后保持 0 附近。
2. **回前台补一次合法重摆**（`onAppForeground` / `onPageShow`）：若后台期间 `curIndex` 变过就 `scrollTo(0)`，然后 `followFrontier(currentSpeechOffset(), 'recenter')`（`recenter` 会重置地板）。回退：删这两个 hook。
   验收：回前台 ≤1 秒内出现 `pos|y≈0` 且 `hi … inScreen=1`，`scrollcmd|src=recenter` 有记录。
3. **终止性早退绕过节流**：`no-back`/`frozen`/`chapter-nowait` 用 `followNote(why, true)`。零行为影响，只为取证。
4. **估算路按 `maxScroll` 夹取**（`Reader.ets:1542` 现为 `maxScroll + band`，而 realC 路是 `[0, maxScroll]`）—— 这是**另一条**（章末目标够不着），与本死锁不同因，**单独一单**再动，别与 1/2 同包。
