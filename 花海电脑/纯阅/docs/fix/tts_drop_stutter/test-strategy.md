# 验证测试策略初稿：听书丢字顿挫

> 关联问题: TTS-DROP-001
> 文档性质: 初稿（供后续详细测试文档展开）
> ❗本域判据铁律：**听感类只能真机验**；「位置/时序」类判据只认日志序列，截图不作判据；模拟器不做长时任务校验、drop 恒 0，**不能当本域验收环境**（只能跑离线门禁）。

## 一、测试范围

### 1.1 受影响模块

| 模块 | 修改类型 | 测试优先级 |
|------|----------|------------|
| `BookSpeaker.ets` 段推进/写管线（FIX-002 尾字节、FIX-003 段内闸） | 逻辑修改（条件触发） | 高 |
| `BookSpeaker.ets` 诊断日志（FIX-001） | 只加日志（零行为） | 高（先自证量具） |
| `BookSpeaker.split()` 分段 | 不改，仅补门禁（FIX-005） | 中 |
| `Reader.ets` 高亮跟随 | 本单不改 | 回归观察 |
| 后台保活链路 | 禁止改动 | 回归（防误伤） |

### 1.2 功能点清单

- [ ] 自动推进路径：段尾 PCM 不再被清（drop 归零）
- [ ] 用户主动跳段路径（nextSeg/prevSeg/jumpTo）：仍立即清队列（意图改变）
- [ ] 哑巴段（0 字节）跳过逻辑不回归（不上报 onSeg、不滚动）
- [ ] 段内 300ms 闸（若落地）：首字延迟可控、欠载计数下降
- [ ] 空段跳段、自播/回落、长时任务自检行不受影响
- [ ] 高亮跟随与声音同步性不劣化（H-D 观察项）

## 四、测试建议

### 4.1 扩展方向

1. **测试数据准备**：固定两本验收书（《剑来》长章 + 《使用说明》符号密集），书目与章节写死，保证改前/改后同章对照；
2. **自动化**：`split()` 零丢字、推进判据钉死可全自动（FIX-005）；真机日志回收可脚本化（分段 recv `tts_diag.txt`，防 TRUNC 覆盖）；
3. **性能**：诊断行本身节流（每 50 句心跳），取证包需量一次日志写入对播放无扰动（uf 不因日志上升）；
4. **噪点（04 #6）**：本策略不覆盖，先按三类分类（边界咔/持续沙沙/蓝牙爆音）另立单。

### 4.2 注意事项

- ❗一次只改一个变量、单独出包（04:236 纪律）；FIX-002 与 FIX-003 **禁止同包**。
- ❗`tts_diag.txt` 每次开始朗读 TRUNC ⇒ 分段场景必须分段 recv。
- ❗取证前核对日志流心跳（宿主机时间 vs 末行时间戳），孤儿 hilog 收工必杀。
- ❗手机上诊断包（md5=**0603f250**…，1,382,271 B，构建 10:50:24 / 装机 10:51:02，见 M-001 §一）与日常版（903e3932…）别搞混；取证结束装回哪个包要写进验收记录。（原写 33c312a8… 是 10-16 旧诊断包，已更正。）
- ❗红线五条（fix-plan §2.4）任何测试不得诱导实现方绕过（如「顺手加个预取看看」）。
