## 四、表3 段内欠载分布（最重要；FIX-003 触发判据）

⚠️ `odd` 行是**择优打印**（仅异常段），所以占比一律以窗口段数 387 为分母，不能拿 63 条互除。tick 每 50 段 1 条属无偏抽样；uf 采样间隔 **200 ms**（`onTick`）。

| 指标 | 实测 |
|---|---|
| uf>0 段 | **39 / 387 = 10.1%**（采样内 39/63）；uf=-1（没读到）**0** 段；Σuf=**86** |
| stockMin<0 段 | 采样内 **44/63 = 69.8%**；无偏 tick 子集 **6/8 = 75%** |
| stockMin 分位（采样内） | p10 **−243** / p50 **−117** / p90 **+29** / min **−419** / max **+117** ms；欠载段中位 −155.5 |
| **ufAt 直方图** | −1：35（55.6%）｜0~100：**0**｜100~300：**0**｜300~600：**0**｜600~1000：1（1.6%）｜>1000：**27（42.9%）** |
| ufAt≥0 分位 | n=28，p50 **1776 ms** / p90 **2620** / min **769** / max **2768** |
| **ufAt 落在段内哪里** | 段首(<0.3×dur) **0 段** ｜ 段中(0.3~0.7) **0 段** ｜ **段末(>0.7) 28/28 = 100%**，且 **28/28 满足 ufAt ≥ dur** |
| 段末空转 | `skew`（章内 墙钟−累计音频）3,654 ms → 20,405 ms，386 段净增 **16,751 ms = 43.4 ms/段**（≈每段均长 2.47%） |
| `written_ms − dur` | **20/63 严格相等**，其余落在 [−214, +231] ms（编排者复算；子 Agent 报的 50/63 有误，按文件修正）⇒ 合成侧**没少字节** |
| odd 成因分解 | `uf>0` 39 + `0≤stockMin<40` 16 = 55，**零重叠、零 dropNow、零 drift** |

**判读**

1. **FIX-003（300ms 段内闸）不成立**：闸只在段首 300 ms 内护住供给，而实测欠载**100% 发生在段末**（最小 769 ms，全部 `ufAt ≥ dur`）——闸介入的时刻计数器还没动，救不了。
2. 真形态是 **段界供给断档**：每段音频本身写全了（`written_ms ≈ dur`），但本段音频放完的瞬间渲染器已见底（`stockMin` 中位 −117 ms），下一段 PCM 还没进来 ⇒ **每段一次、约 43 ms 的静音空档**。这与 M-001（另一单）实测的「段界空隙 p50=59 ms」是同一件事，量级一致。
3. 因此「丢字」的机理**不是** H-A（清尾吃字节，实测 20.6 ms/章可忽略），**也不是** H-C（哑巴段，本窗口 0 次），而是 **H-A3 消费侧脱钩 + 段界零缓冲**：断粮窗口（数十 ms）+ 墙钟照走 + 高亮已按墙钟跳到下一句 ⇒ 听感是「顿一下、几个字没了、后面又正常」。

## 五、量具缺陷（本轮实测发现，需在下一次出包前修）

1. ❗**`odd` 判据把真欠载排除在外**：`BookSpeaker.ets:1063-1064` 为 `(stockNow >= 0 && stockNow < 40)` —— 负值（确凿欠载）被 `>= 0` 挡掉，不落盘。实测有 6 段 `stockMin<0 且 uf=0` 只在 tick 行出现 ⇒ 异常段被系统性漏记。建议改 `stockNow < 40`（去掉 `>= 0`）。
2. ❗**`dropSegPct` 分子分母基准不一致**：分母 `diagSegN` **全会话累计、从不归零**，分子 `diagDropSegs` 在 `setChapter()` 按章归零 ⇒ 第 2 章起占比被系统性低估。本轮之所以没影响结论：drop 仅 660B（20.6ms），怎么算都是 0%。
3. `align|odd` 同样按章归零，而 dropsum 每 50 段才吐一次且跨章不清零 ⇒ 读数要按章切分。
4. `ufAt` 分辨率 200 ms ⇒ **<200 ms 的段首欠载原理上不可见**；「0 段段首欠载」只能表述为「≥200 ms 分辨率下无」。

## 七、结论与下一步
