## 二、改法（最小改动，只碰两处）

### F1 `onFontMetricsChanged()`：字号/行距变化 → `endReachY = -1`

真实底部随字号一起变，旧值不能再当「到底」判据。作废后等 List 在新字号下重新报一次。
⇒ 消灭"40→49 直跳"。

### F2 `followFrontier()`：居中目标上界用真实底部压制估算

```ts
const effMax = (this.endReachY > 0 && this.endReachY < this.maxScroll) ? this.endReachY : this.maxScroll;
const want   = Math.round(Math.max(0, Math.min(effMax + band, centerY - band / 2)));
```

- 只会在「List 报过真实底部且它比估算小」（= 估算偏高）时生效；估算偏低时行为完全不变
  （保留 `+ band` 余量，不影响此前修的「章末按钮滚不出来」）。
- ⇒ 视图不会被顶到估算的假底部，高亮跟着朗读位置留在屏幕内。

## 七、治本（同日续修，提交 17eda84）

### 7.1 尺子自校正（治「估算比真实多算几屏」）

实测（自用真机日志 + 模拟器探针）：模型 `perLine = floor(视口宽 ÷ 字号)`
在字号 30 时算出 10 字/行，而隐藏 Text 实测真实能放 **11** 字/行；模型每段还要 `ceil(段单位数 ÷ perLine)`
⇒ 短段落多的正文逐段多算一整行 ⇒ 累计 23%（=5 屏）。误差**随字号变大**（字号18 时 1.009、字号21 时 1.231）。

改法（一个变量：比例）：
1. 正文每块的 ListItem 挂 `onAreaChange` 量**真实渲染高度**；
2. 与模型块高对比 ⇒ `r = Σ真实 / Σ模型`（≥3 块且合计够高才算，节流 700ms，变化>0.8% 才重算）；
3. 比例按 `字号_行距_宽` 存设置（`rulerScales`）⇒ 换字号/下次启动直接生效；
4. `measureBlocks()` 用 r 压回 `blockTops / contentHeight / maxScroll`，校正后按「当前字」落回原位；
5. 换章/换窗口/改字号 ⇒ 实测样本作废重学（避免用旧字号的样本污染比例）。

实测收敛结果（模拟器，字号30，本书本章）：
| 指标 | 校正前 | 校正后 |
| --- | --- | --- |
| 模型 max vs 真实底部 | 差 2.5%（模型偏低） | **差 0.7%**（真实 16509 / 模型 16621） |
| 用户那本书（字号21） | 差 23% | 机制相同（按书按章实学） |

## 九、收口（提交 7c1e9bc）：改字号时必须**重铺窗口**

用户口径（2026-10-16 更晚）：「改完字体行距后要退回书架重进貌似才正常」——这句话直接指路。

### 根因

改字号后虽然重算了尺子（`measureBlocks`），但**列表没有重建**：懒加载 List 在「内容重排但没有滚动」时
**不会再回调 `onScrollIndex`** ⇒ 它内部/我们缓存的「顶部是第几块」一直是旧值 ⇒ 视口顶部块/字算错，
页码与高亮跟着错。而「退出书架重进」会走 `buildWindow`（`winKey++`、重置块序号 ⇒ List 彻底重建），所以一重进就正常。

### 改法

`onFontMetricsChanged()` 里在重算前先 `buildWindow(this.curIndex)`（= 重进书走的那条路），
再 `rebuildPages()` → `measureBlocks()` → 按「同一个字」`restoreScrollToOffset(anchor)` 落位。

### 实测（模拟器，hilog 全程可核）

| 场景 | 结果 |
| --- | --- |
| 单次放大（字号 34→35） | `window ch=9..9` 重铺 ✓、`paging fs=35`、`max 20293→20907`、**`inCh 401→406`（同一个字）**、`curY 3046→3173` ✓ |
| 连按 4 次（35→39） | **`inCh 418→407`**、`max 20907→23479`、页码 `6/41→6/45`（同一位置）✓ |
| 稳定性 | 无崩溃（pid 前后一致），窗口重铺 6 次（每次按键一次，符合预期） |

## 十、续修（提交 6ad5139）：连点字号的锚点漂移 + 可视高变化重算页表

用户真机（rebuild 包）：「新包修改字号和行距后还是需要返回书架，不然页码还是错的」
从该日志量出的两个残留缺陷（都还在「改字号/行距」这条路上）：

### 缺陷① 连点字号时锚点被中间态覆盖（每次掉 ~1 页）

日志实证：连点 A+/A− 时 `inCh` 逐次掉 ~350 字（≈一页）。原因：第 2 次之后 `currentOffset()`
读到的是「上一次落位还没走完」的中间态（`restoreScrollToOffset` 有 60/200ms 两次补正，落在中间就被当成新锚点）。

改法：`onFontMetricsChanged()` 里 800ms 内**沿用同一个锚点**（`anchorHold/anchorHoldAt`）。
实测（模拟器，连点 4 次放大）：`inCh 111→100`（同一个字），页码 `1/41→1/45`（同位置、总数随字号更新）。
（改前同场景掉 ~350 字。）

### 缺陷② 可视高变化没有重算页表（滚动模式）

`List.onAreaChange` 原来只 `measureBlocks()`（重估行数/内容高），**没有 `rebuildPages()`** ⇒
面板开关/旋转/分屏改变可视高后，页表仍是按旧可视高算的 ⇒ 页码错到「退出重进」为止（那时可视高已定）。
改法：可视高/宽变化时先按「当前字」锚住 → `measureBlocks()` + `rebuildPages()` + `restoreScrollToOffset()` + 标签刷新。

门禁：font_metrics 新增 UT-216d（锚点保持）、UT-217（可视高变化必须重算页表），并修正 UT-216a 匹配新写法；
page_label、diag_log_reset、check_both 双版本 —— 全 GREEN。
交付：`release/_wip/entry-default-signed-anchorhold-release.hap` md5 `723f1afbbc56016645115feaae1850bb`
（飞书 `om_x100b622eeb6d30a0df28ef33032e6e6`）。

### 经验（写死）

凡「重排」类操作（改字号/行距、面板开关、旋转、切模式）都必须同时满足三条，缺一条就会「要重进才对」：
1. **按同一个字锚住**（不能用像素，更不能在落位中途再取锚点）；
2. **重算尺子**（`measureBlocks`）**和页表**（`rebuildPages`）；
3. **重铺窗口**（`buildWindow`：懒加载列表否则不再回调 `onScrollIndex`，顶部块序号一直沿用旧值）。

### 判读口径（下次拿到日志先看这三条）
