## 二、测试类型

### 2.1 单元测试（离线门禁，先红后绿）

**目标**：把 `centerTarget` / `pixelOfLocal` / `measureBlocks` 的**纯算术**做成可复算的门禁，不依赖设备。

| 测试项 | 测试内容 | 优先级 |
|--------|----------|--------|
| UT-001 | 章首短句：`want` 不得小于 0（下界夹取保持），且过冲放宽后目标 ≥ `maxScroll` 时不被提前夹死 | 高 |
| UT-002 | 章末长章：`centerY − band/2 > maxScroll` 时，修正后 `want > maxScroll`（⇒ 视图可达真实底）；修正前 `want === maxScroll`（红） | 高 |
| UT-003 | 末块插值：末块内任意 `local` 的 `pixelOfLocal` 必须 ≥ `blockTops[末块]`，且块内跨度 ≥ `linesOf(末块)×lineH`（修正前跨度恒 = 1 行高，红） | 高 |
| UT-004 | `contentHeight` 不含块外内容（正文块之外的首按钮/页脚/padding 不在估算内）——**断言现状事实**，作为 FIX-002 用官方留白而非改尺子的依据 | 中 |
| UT-005 | `RULER_SCALE` 静态性：源码形状断言 —— 系数为常量、不得出现运行时刷新它的调用（反向：把刷新调用塞进去必须报错） | 中 |

**边界条件**
- [ ] 短章（内容不足一屏）⇒ `maxScroll = 0`，任何目标都必须夹到 0 且不抛错
- [ ] 章首首句（`localFrom = 0`）与章首非首句
- [ ] 末句恰为章内最后一个字符（`localTo = len−1`）
- [ ] 空段/哑巴段（0 字节合成）跳过时不得上报高亮（与定位正交，但用例要覆盖不回归）
- [ ] `band` 由 `viewportHeight − blockedH()` 得出（`blockedH()` 现恒 0，`Reader.ets:1176-1178`）

**运行方式（门禁命令）**

```bash

python tools/shelf_selftest/run.py                  # 既有：书架（回归）

```

```

python tools/reader_center_selftest.py --expect-green              # FIX-001/004 落地后收口用（五组全绿断言）
```

### 2.2 集成测试（真机 + 日志）

**目标**：验证「跟读目标能到、且到得准」，以及页脚可见性。

| 测试项 | 测试场景 | 判据（原始日志字段） |
|--------|----------|----------------------|
| IT-001 | 长章听书全程，滚动模式 | **以截图为据**：高亮所在行距可视区顶落在视口中部带内；`dev` 仅作同章前后对照（M-001 实测 dev 与画面差 130~200vp） |
| IT-002 | 「没滚到目标」比例 | `want − curY > 一行高` 的比例 < 5%（改动前基线 ~51%，见 `03` §J） |
| IT-003 | 章末 8 条序列 | 不得出现「`want` 反复相同 + `curY` 反复停同一值 + 差 > 一行高」（夹死铁证） |
| IT-004 | 章末页脚 | `uitest dumpLayout` 能取到「下一章」控件且 `bounds` 在屏内；截图目视可见 |
| IT-005 | 章首 5 条序列 | 口径 B：**不要求居中**；`dev` 须稳定、无逐 tick 抖动，且首句距顶 ≤ 0.35×band（偏上属已知设计行为） |
| IT-006 | 模式不被偷改 | `tts setChapter: … mode=scroll` 且全程无 `switch-in/switch-out` |
| IT-007 | 跨章自动推进 | 章末读完自动进下一章，且下一章章首定位不跳回章头乱处 |

❗**判据说明（M-001 实测后修正）**：`dev` / `hrel` / `hrelEnd` 都是「估算像素 − 真实像素」的混算（`Reader.ets:1037` / `:779`），M-001 现场实测同刻 `hrel=−641` 而截图上高亮在屏内约 48%×band（差 0.8~0.9×band）⇒ **绝对位置一律以真机截图量像素为准**，`dev` 只用于「同章前后是否收敛 / 有没有逐 tick 抖动」。
**基线（M-001，ch229 章末 / ch230 章首）**：章末 `want=26649 = round(maxScroll)` 恒定 12.6s、`curY=26471`、`dev` 恒 208~209；章首 `want=0 / curY=0`、`dev` −367 → −83（首句距可视区顶 21vp）。**该章章末按钮可见（D1 未复现）⇒ 验收必须挑「按钮不可见」的章**。

**取证纪律**：
- 抓日志前先核对「宿主机时间 vs 日志最后一行行首时间戳」（差 1~2 分钟即这条 `hilog` 流已死，读到的是旧数据 ⇒ 全部结论作废）。
- 命令：`hdc -t <ip>:5555 shell hilog -r` → 点「开始朗读」→ 等 20~40s → `hilog -x -T reader` 拉全量再 grep `center follow` / `tts setChapter` / `BookSpeaker: seg done`。
- `hilog` 被流控吞日志时改用 `dumpLayout` + 截图当判据。

### 2.3 回归测试

**回归范围**
- 核心功能：翻页模式听书（`hrel/hrelEnd/band` 判据）、滚动模式手动滚动、章首/章末按钮**点击**切章、阅读设置面板、听书面板自检行。
- 关联功能：进度锚写入/恢复（`save pos` ≠ 判据，看强杀重开的 `restore pos`）、后台/息屏听书跨章、自动滚动（`Reader.ets:3220` 的 `currentY() >= maxScroll − 8`）是否因留白提前换章、章末页码胶囊（`R:3647-3651`）是否仍显示 `N/N`。
- 布局类改动（`contentEndOffset`/`contentStartOffset` 会改变可视区）：**中英两种语言各截图复核一遍**（英文标签长度是中文 1.5~2 倍）。

### 2.4 场景测试

| 场景 | 操作步骤 | 预期结果 |
|------|----------|----------|
| S1 章首 | 打开长章 → 点开始朗读 → 看前 5 句 | 首句停在屏幕上部（约 9~20% 屏高）、不贴顶、无抖动（口径 B：不插留白、不硬居中） |
| S2 章末 | 听到最后 2~4 句 | 视图继续滚到末尾，末句可见，`上一章/下一章` 按钮出现且可点 |
| S3 章末跨章 | 章末不点按钮，等读完 | 自动进下一章，首句定位正确（不回到上一章位置、不跳到章头乱处） |

| S7 空段/哑巴段 | 听含大量符号/破折号的章节 | 不卡推进、不出现「高亮乱跳句」，无声段被静默越过 |

## 四、测试建议

### 4.1 扩展方向（建议在详细测试文档中展开）

1. **测试数据准备**：挑一本「长章 + 含超长段落 + 含符号哑巴段」的书（如《剑来》）作为固定样本；记录样本章的估算 `contentHeight`、真实内容高、页脚真实高，作为每次回归的对照基线。
2. **自动化测试**：把「真机取证」脚本化 —— `tools/reader_pos_smoke.sh` 已有 `hdc` 驱动骨架，可扩展为「启动 → 开朗读 → 拉 `center follow` → 解析 `dev` 分布 → 判定 PASS/FAIL」，产出机器可读结果。
3. **性能测试**：`contentEndOffset` 与动画中重入 `scrollTo` 的帧率影响（改前先建基线；官方提示动画速度 > 200vp/s 时滚动区内组件不响应点击，需确认章末按钮点击不被吞）。
4. **安全/健壮性**：`contentStartOffset + contentEndOffset` 超过内容区长度会被官方**一起置 0**（短章/极短章节）⇒ 补一条「短章不得因留白导致内容跳动或按钮消失」的用例。
5. **口径测试**：把「章首不插留白、不硬居中」（2026-10-16 用户拍板 B）固化进 `01-纯阅功能规格.md` §2.4，避免下次又被当成 bug 反复修。

### 4.2 注意事项

- **一次只改一个变量**：FIX-001/002/003/004 各自单独出包真机验；改动叠加后无法归因（本项目整晚回退的教训）。
- **先量再改**：M-001 的测量数据是 FIX-004 是否开工的唯一依据（残差 ≤ 1 行高就不动尺子）。
- **不许拿日志数字直接当结论**：app 自报的 `band`（= `viewportHeight`，`blockedH()` 恒 0）与实际正文可视区并不一致 ⇒ 关键判定要配「连状态栏/底部面板一起拍的」真机截图，量像素后判定。
- **不许用 `onScrollFrameBegin`** 去"学"真实剩余距离（官方明文不因程序化滚动触发）。
- **留白常量不要取大**：越大越容易出现「章末大段空白」的观感问题；并用短章用例兜底。
