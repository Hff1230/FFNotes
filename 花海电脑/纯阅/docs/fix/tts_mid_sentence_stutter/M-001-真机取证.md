## 8. 实测 vs 未确认

**实测（有原始日志/脚本输出）**
- 段界空隙：RUN2 n=604 中位 59 ms / 最大 200 ms / >50 ms 占 54.0% / >150 ms 占 8.6%；RUN1 n=147 中位 48 ms / 最大 249 ms。
- 提前量 `dur−played`：中位 21 ms、最大 120 ms（两轮一致）。
- 语速 cps 中位 5.60；段长 ch230 `683/23/9`、ch231 `502/24/10`。
- 三类硬错误计数：0 / 0 / 2。
- 模式 = 上下滚动（日志 `mode=scroll`）；连续播放 ≈19.5 min；自然跨 1 章。
- 屏幕被 UU远程/ToDesk 占用并反复抢占（窗口/进程日志佐证）。

**未确认 / 与预期不符**
- ⚠️ **提前量与 `fix-plan §1.3-H4` 预期不符**：预期 120~320 ms，实测中位仅 21 ms、上限 120 ms ⇒ H4 的「120 ms 容差 + 200 ms tick」在**本包**上不成立（更接近「40 ms 容差」口径）。**据此，H4 作为「放大器」的因果关系需重新判定。**
- ❓ 段界空隙 59 ms 的**听感可辨性**未由用户确认（无用户在场）。
- ❓ 顿挫落点是否真在**逗号处**（段界）而非**词中间**（段内）——本报告只证明「段界有 59 ms 级空档」，**未**排除段内亦有问题（段内块间空隙照旧无日志、未测）。
- ❓ 扬声器 vs 蓝牙对照（§1.4-C）未做 ⇒ 「59 ms 是否被蓝牙链路放大」未知。
- ❓ 「亮屏即停朗读」仅 1 次观察，未复现验证。
