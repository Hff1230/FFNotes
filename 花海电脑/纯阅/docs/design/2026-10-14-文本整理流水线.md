# 纯阅 · 文本整理流水线

> **一句话结论**：**要，但要分成两层做** —— ① **清洗**（必须、安全、默认开）② **结构规范化整理**（有价值、可控、默认保守 + 可开关 + 可撤销）。
> **铁律**：**原文永不改写**（改写原文会砸掉位置锚 `offset`、且不可回溯）；整理结果落在 sidecar / 显示层，随时可重跑、可还原。

## 一、现状（代码事实，别重复造）

| 层 | 已有什么 | 缺口 |
|---|---|---|
| 解码 | 编码嗅探（gbk/gb2312/gb18030 → gb18030）、**流式解码**（跨片半汉字）、去 UTF-16 的 0 填充、2MB 分片装载 | UTF-16 之外的少见编码；BOM 处理 |
| 行级清洗 | `TextUtil.normalize()`：**只做三件事** —— 去控制字符、`\r\n`/`\r` → `\n`、全角空格 `\u3000` → 半角 | ① **本地 txt 没走垃圾行表**（只有抓取侧走）；② 无行尾空白清理；③ 无连续空行压缩；④ 无"TXT下载/手打版/校对版/手机电子书"这类本地常见行 |
| 章节识别 | `CHAPTER_LINE_RE`：第X章/节/回/卷/部/篇/集、Chapter/Chapitre/Kapitel/Capítulo/Глава/제N장/序章/前言/后记/番外；三轮匹配（含"按章号数字对"）；首章前内容并入第一章 | ① **卷/部与章同级**（目录没有层级）；② 标题里的站点后缀（`（1/2）`、`_全本`、`最新章节`）没清；③ **缺章静默跳过**（跳号不提示）；④ `MAX_CHAPTER_CHARS` 切的「（续 N）」在目录里不折叠 |
| 抓取侧 | `TextUtil.cleanChapterBody()` + 垃圾行表（站点水印 / JS 残渣 / 分页提示，实测来源：`最新网址：www.xbotaodz.info`、`play("code-2");`）；`BookSourceService.normalizeToc()` 整理目录 | HTML 实体还原（`&nbsp;`/`&#12290;`）、`<br>` → 换行、去"本章未完/下一页"等**站点成句噪音** |
| 段落/排版 | 渲染层控制（`fontSize=18`、`lineHeight=1.7`、4 主题） | **没有段首缩进、没有段间距控制**、没有"段落是否合并"策略 |

## 二、设计：四段流水线（S1→S4）

```
S1 解码层（已有，补齐）
   → S2 行级清洗（补齐 + 本地侧同享）
      → S3 结构规范化（新增：标题统一 / 卷章层级 / 缺章占位 / 续章折叠）
         → S4 显示层策略（不改文本：缩进 / 段距 / 空行显示）
```

**S2 行级清洗（安全项，默认全开）**
- 统一换行、去控制字符、去零宽字符（`\u200b-\u200f`、`\ufeff`）、行尾空白、连续 ≥3 空行 → 1 空行；
- 垃圾行表**两侧共用**（本地也过）：`最新网址/请记住本站/本站域名/公告/广告/扫码关注/更多精彩小说/手机用户请浏览/TXT下载/手打版/校对版/全集下载`；
- 分隔线行（`-----`、`=====`、`＊＊＊`）→ 统一为空行或删除（可开关）；
- **只删"整行命中"的行**（不碰行内），并有**删除计数**用于报告。

**S3 结构规范化（分批做，默认保守）**
1. **标题规范化**：去掉标题里的站点尾巴（`（1/2）`、`_全本`、`最新章节`、`最新章节请记住`），保留原章名文字；**编号解析统一**（汉字数字与阿拉伯数字都解析出章号，**不改变显示原文**）。
2. **卷 / 章层级**：`第X卷/部/篇` 作为**分组**（目录可折叠），章在其下；现在它们同级 → 长书目录呈现会差很多。
3. **缺章占位**：章号跳号（如 800 → 802）→ 目录里插「**第801章（缺）**」占位并可点击"去书源补章"（与 `ShelfAutoUpdater` 已有能力联动），**不再静默跳过**。
4. **续章折叠**：`（续1）` 在目录里折叠到同一章下（正文仍分段渲染，避免一屏几十万字）。
5. **段落规范化**：段首缩进/段间距**在渲染层做**（配优化方案的 P1-13），**不改文本**。

**S4 显示层**：段首缩进 2 字符、段间距、是否显示空行 —— 全是"显示策略"，与文本无关，可随时切换。

## 三、必须守住的（与红线的交叉点）

1. **原文永不改写**：整理只产出**规则 + sidecar 元数据**，渲染时应用；可选"导出整理后 txt"作为**另存**功能，不覆盖沙箱正文。
2. **位置锚不受整理影响**：`offset` 定义在**稳定文本**上；整理规则升级（= 文本可能变化）时，必须按「**章名 + 百分比**」重定位，并沿用现有的三态回退；**任何情况下不许因整理导致进度丢失**。
3. **幂等可重跑**：同一份文本跑两次规则结果必须一致；规则带版本号（`rulesetVersion`），升级后可一键"重新整理"。
4. **不过度整理**：正文里出现"第3章"字样、古诗/歌词、代码块 → 一律**不合并、不删**；标题识别只认"整行且模式命中"（现有 `CHAPTER_LINE_RE` 已是整行匹配，保持）。
5. **只删整行**：行内出现"本站"等词不许误伤正文。

## 四、待拍板（3 条）

| # | 问题 | 默认建议 |
|---|---|---|
| 1 | **整理结果放哪**：A 只做 sidecar/显示策略（原文不动）／B 另存"整理后 txt"（用户可导出）／C 直接改写沙箱正文 | **A（+ 可选 B 作导出）**；**C 不做**——会砸 `offset` 与不可回溯 |
| 2 | **默认强度**：① 保守（只做安全项：换行/控制符/垃圾行）② 标准（+ 标题统一/卷章层级/缺章占位）③ 激进（+ 段落归一/合并/去分隔线） | **保守默认 + 每项开关**；标准项做成"一键整理"由用户点 |
| 3 | **整理是否可见**：要不要给用户「**整理报告**」（删了 N 行水印、修了 M 个标题、发现 K 个缺章）+ **一键还原**？ | **要**——这是把"整理"从玄学变成可信任功能的关键 |

## 五、验收判据（可量化，不留"看起来好了"）

| 项 | 判据 |
|---|---|
| 目录准确率 | 抽检 50 章（跨卷/跨续章/含前缀章名），准确 ≥98% |
| 垃圾行残留 | 抽 20 章，站点水印/广告行**残留 0**（本地 txt 与抓取各抽一份） |
| 乱码 | 打开 10 本不同编码的书，乱码字符 **0** |
| 进度不丢 | 整理前后同章同名；重进落点误差 ≤1 屏（走 04 的阅读进度验收） |
| 整理耗时 | 21.9MB 书后台整理 ≤1s，且**不阻塞首屏**（首屏 ≤1.5s，见优化方案 P1-4） |
| 报告一致性 | 报告里的"删除 N 行 / 修 M 个标题"与实际 diff 完全对得上 |
| 幂等 | 同一书连跑两次，报告数字与目录**完全一致** |

## 六、排期建议（成本低→高）

1. **S2 补齐 + 抓取/本地共用垃圾行表**（最小改动、立刻见效：本地 txt 广告行、行尾空白、连续空行）——建议先做；
2. **整理报告 + 一键还原**（把已有清洗的成果显性化，用户立刻能感知）；
3. **S3-1 标题规范化 + S3-3 缺章占位**（目录质量提升最明显）；
4. **S3-2 卷章层级**（目录结构，配合目录 UI 改造）；
5. **S3-4 续章折叠 + S4 段落显示策略**（配优化方案 P1-13 排版批次）。

## 七、边界（本文没做的）

- 未改代码、未跑真机；**没有实测"本地 txt 广告行残留率"**（需抽样 10 本本地书统计，属第一步的输入）；
- 未评估繁简转换、OCR 错字纠正（属"激进"档，风险高，先不做）；
- 未设计"整理规则"的配置文件格式（等 §四 拍板后再落）。
