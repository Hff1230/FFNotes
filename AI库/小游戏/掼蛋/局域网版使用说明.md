**■ 掼蛋 - 局域网版使用说明**

---

**■ 系统要求**

**▍ 服务器端**

- Node.js **18.14+**（跑单元测试 `npm test` / `运行测试.bat` 需要 —— jest 30 要求 `^18.14.0`）；只跑服务端的话 14.0+ 即可
- 操作系统: Windows/Linux/MacOS
- 网络端口: 8081 (确保防火墙允许此端口)

**▍ 客户端**

- 现代浏览器 (Chrome/Firefox/Edge/Safari)
- 网络连接: 与服务器在同一局域网

---

**■ 安装步骤**

**▍ 1. 安装Node.js**

访问 [Node.js官网](https://nodejs.org/) 下载并安装最新LTS版本。

验证安装:
```bash
node --version
```

**▍ 2. 安装依赖**

在游戏目录打开命令行,运行:

```bash
npm install
```

这会安装：
- `ws` - WebSocket库
- `nodemon` - 自动重启工具（开发依赖）
- `jest` - 单元测试框架（开发依赖，`npm test` 用）

**▍ 3. 准备游戏文件**

确保以下文件在同一目录中:
- `guandan-server.js` - 服务器程序
- `guandan-lan.html` - 游戏客户端
- `package.json` - 项目配置
- `guandan.test.js`、`ai-players-test.js` - 测试代码（可选，只跑游戏时不需要）
- `docs/` - 审查与修复方案文档（可选）

> 完整文件清单见文末「文件说明」。

**■ 服务器设置**

**▍ 方式一：双击启动（推荐新手）**

在游戏目录中，双击以下文件即可启动：

| 文件 | 说明 |
| --- | --- |
| `启动服务器-自动重启.bat` | **开发推荐** - 用 nodemon 启动，改代码后自动重启；按 `rs` + 回车可手动重启（nodemon 专属） |
| `启动服务器-普通模式.bat` | 直接 `node` 启动；没有 nodemon，服务器**内置 `fs.watch` 自重启**（监视 `guandan-server.js` / `guandan-lan.html`；v2.1.3 起为**同进程原地重启**：**进程不退出、PID 不变**，房间会清空 —— 与 nodemon 重启同语义），没有 `rs` 快捷键 |

> 💡 **提示**: 这两个 `.bat` 发现没有 `node_modules` 时会自动跑 `npm install`（自动重启模式还会单独检查并装 nodemon）。

**▍ 方式二：命令行启动**

在游戏目录打开命令行:

**自动重启模式（开发推荐）:**
```bash
npm run dev
```

**普通模式:**
```bash
npm start
```

> 💡 **提示**: 命令行方式需要自己先装好依赖（第一次先跑一次 `npm install`）；「自动安装依赖」是上面两个 `.bat` 的行为。

**■ 客户端连接**

**▍ 方法一: 本机测试**

1. 打开浏览器
2. 访问: `http://localhost:8081`
3. 输入名称，点击牌桌加入或创建新桌

**▍ 方法二: 局域网连接**

1. 确保服务器已启动
2. 在同一局域网的其他设备上打开浏览器
3. 访问: `http://[服务器IP]:8081`
   - 例如: `http://192.168.1.100:8081`
4. 输入名称，选择牌桌加入或创建新桌

> 💡 **提示**: 服务器启动后会显示本机IP地址，直接分享给其他玩家即可。

**▍ 牌桌列表**

登录后会显示所有牌桌：
- **空桌**: 点击即可加入
- **游戏中**: 显示蓝色边框，可以点击"观战"按钮进入观战
- **已满**: 显示红色边框，无法加入
- **创建新桌**: 点击 "+" 卡片创建新牌桌

**▍ 观战模式**

**创建房间时**「👁️ 允许观战」**默认就是勾上的**（服务器 `allowSpectator !== false` 默认允许观战）；不想让人观战，把勾去掉再开房即可。

游戏进行中的牌桌如果开启了观战模式，会显示"👁️ 观战"按钮：
1. 点击"观战"按钮进入房间
2. **观战者只能看本房玩家（在座四人）的手牌**，点击头像 / 玩家名字可切换视角
3. 点击其他玩家名字可切换查看其手牌
4. 观战者只能观看，无法出牌
5. 可以正常使用聊天功能

> 💡 **提示**: 房间号旁边有 👁️ 标识表示该房间允许观战

**▍ 观战鉴权（v2.1.3 服务端修复）**

- **只能看本房的牌**：观战视角由服务端按「本房在座玩家」校验 —— 请求看别房玩家或不存在的座位会被拒（`VIEW_OUT_OF_RANGE`：「观战视角越界：只能查看本房间内玩家的手牌」），入场时的初始视角同样校验，别家的手牌不会再被透出去。
- **切换视角已修复**：客户端「切换视角」此前把**被观看玩家的 id** 错当成观战者自己的 id 发给服务器，服务端判据恒不成立 → 点了**静默没反应**；现在按「自己的观战身份 + 想看的玩家」两个字段正确发送，切换真的生效。
- **观战身份也要令牌**（见下文「会话、身份与限额」）：伪造观战身份替别人改视角会被拒（`NOT_SPECTATOR`：「当前连接不是观战身份，无法切换观战视角」）。

**▍ 游戏流程**

1. 输入名称（最长 **16 字**，超出截断；昵称一律按纯文本显示）
2. 点击牌桌加入 或 创建新桌
3. 等待4人齐后点击"准备"
4. 全部准备后游戏自动开始

**■ 游戏界面**

**▍ 桌面布局**

游戏以圆桌形式显示，玩家位置如下：

```
        [3号位]
           │
    [4号位]─┼─[2号位]
           │
        [1号位]
```

- **1号位**: 屏幕下方（自己）
- **2号位**: 屏幕右侧（逆时针下一个）
- **3号位**: 屏幕上方（对面，对家）
- **4号位**: 屏幕左侧（逆时针上一个）

**▍ 出牌顺序**

按 **1 → 2 → 3 → 4** 逆时针顺序轮流出牌：
- 1号位(下) → 2号位(右) → 3号位(上) → 4号位(左) → 1号位(下)

**▍ 队伍分配**

- **红队**: 1号位 + 3号位（对家）
- **蓝队**: 2号位 + 4号位（对家）

**■ 游戏规则**

**▍ 基本信息**

- **玩家人数**: 4人（2对搭档）
- **使用牌数**: 2副标准扑克牌（108张）
- **每人手牌**: 27张

**▍ 牌面大小**

```
大王 > 小王 > 级牌(所有花色) > A > K > Q > J > 10 > 9 > 8 > 7 > 6 > 5 > 4 > 3 > 2
```
⚠️ 注意：2是最小的牌！级牌（当前级别的所有花色牌）大于A！

**▍ 队伍分配**

参见上文「游戏界面 - 队伍分配」

**▍ 出牌规则**

1. 按逆时针方向轮流出牌
2. 必须压过上家的牌才能出
3. 可以选择"不出"（过）
4. 同一轮中，所有人都"过"后，最后出牌的一方如果还有手牌则继续领出新牌，如果最后出牌的一方已出完，则由对家接风

**▍ 牌型说明**

| 牌型  | 说明               |
| --- | ---------------- |
| 单张  | 任意一张牌            |
| 对子  | 两张相同的牌           |
| 三张  | 三张相同的牌           |
| 三带二 | 三张相同+一对(可以对小王、对大王)          |
| 顺子  | 固定 5 张连续单牌（不含王）；**可以含 2**，`A2345` 合法（A 作 1）      |
| 连对  | 固定 3 对连续对子；**A 可作 1**，`AA2233` 是最小的连对           |
| 飞机  | 固定 2 组连续三张；**A 可作 1**，`AAA222` 是最小的二连三           |
| 炸弹  | 4张或以上相同的牌        |
| 同花顺 | 5张同花色顺子          |
| 王炸  | 四张王（最大）          |

**▍ 逢人配（百搭）**

- 红桃花色的级牌为"逢人配"
- **可代替除大王、小王以外的任意一张牌**
- 例如：当前打3，红桃3是逢人配（黑桃3、梅花3、方块3只是普通级牌）

**▍ 升级规则**

- **双赢**: 搭档获得前两名 → **升3级**
- **中赢**: 搭档获得第一和第三 → 升2级
- **小赢**: 搭档获得第一和第四 → 升1级
- **升级不能跳过A**：例如打K时双赢升3级，下一局打A（不会跳过A直接获胜）

**▍ 通关规则**

- **必须打A**：队伍升级到A级（14级）后，必须继续打A
- **双赢通关**：只有在**打自己的级牌**时双赢才能通关获胜，结束游戏
- **打对面级牌**：如果打的是对面的级牌（帮忙打），即使双赢也不能通关，只能继续打自己的A
- **非双赢继续**：打A时如果不是双赢，级别保持A继续打

**▍ 进贡规则**

- **单贡**: 第 4 名向第 1 名进贡一张牌 —— 取自己手里**除红心级牌（逢人配）以外最大的一张**。也就是说**大王、小王和其它花色的级牌都可以进贡**，永远不会被进贡出去的只有红心级牌（逢人配）
- **双贡**: 双赢（双下）时，第 3 名和第 4 名都要进贡，第 1 名拿其中最大的一张，第 2 名拿另一张
- **还贡**: 收到贡牌后，需还一张 10 及以下的牌。本实现比官方更严：**王和级牌都不能还贡**（官方只说「10 及以下」，没禁止还级牌）
- **抗贡（单贡）**: 该进贡人**自己手上**有两张大王即可抗贡、无需进贡（只看他自己，不看搭档）
- **抗贡（双贡）**: 双赢（双下）时，**两张大王都在进贡方 —— 也就是要进贡的双下方两位玩家手上合计**，才算抗贡成功，两人都无需进贡
- **没有「抗还贡」**: 本游戏**不存在**「用红心逢人配抗还贡」这类规则（早期文档提到的「抗还贡」是笔误，实现里没有这一条）

**■ 会话、身份与限额**

> 本节对应 2026-10-16 的一批服务端修复（FIX-002/004/005/006/007/008/009）。它们**不改玩法**，但改变了「谁能做什么 / 掉线会怎样 / 输入与消息有什么上限 / 服务器重启后要不要刷新」—— 建议每位玩家都读一遍。

**▍ 会话令牌（开房 / 加入 / 观战 / 重连都会下发）**

- 创建房间、加入房间、观战进入、重连成功时，服务端都会下发一个**会话令牌**（`session token`，UUID 形态）。客户端把它存进浏览器的 `localStorage.guandan_token`，此后**每条动作消息（准备 / 出牌 / 不出 / 托管 / 聊天 / 新局 / 添加 AI / 测试按钮 / 还贡）都自动带上它**，玩家不用操心。
- 令牌绑定在「连接 ↔ 座位」上，是服务端判定「你是不是这个座位的人」的唯一凭据：**另开一个页面、填同一个名字再也顶不了别人的座位**；重连**必须带令牌**，没带或带错一律被拒（`AUTH_FAILED`，且**不下发任何手牌**）。
- **令牌是内存态**：服务器**每次重启**（包括改代码触发的 nodemon 自重启）令牌**全部作废**，所有房间同时被清空。重启后在场所有人的旧页面都需要**按一次 F5 刷新页面**，再重新加入房间。
- **页面上会有可读提示**（不会静默卡住）：
  - 旧标签页重连被拒 / 令牌与连接不符 → 弹常驻红条「⚠️ **会话令牌已失效：请按 F5 刷新页面后重新加入房间**（服务器重启会让旧令牌作废）。」（服务端文案分别为「重连凭证无效或已过期：请按 F5 刷新页面后重新加入房间」与 `TOKEN_MISMATCH`「令牌校验失败：会话令牌与当前连接不符，请按 F5 刷新页面后重试」）
  - 旧页面（改动前就打开、没刷新过）在房内发动作 → 「缺少会话令牌：**请按 F5 刷新页面后重新加入房间**」（`TOKEN_REQUIRED`）
  - 刷新过的新客户端发现 localStorage 里没有令牌 → 「检测到旧版会话信息（缺少令牌），**请按 F5 刷新页面后重新加入房间**」，并清掉旧会话（**不会**陷入「一直重连却永远连不上」）

**▍ 断线、重连与 AI 接管**

| 场景 | 行为 |
| --- | --- |
| 对局中掉线（关页面 / 断网 / 拔网线） | 座位**保留 30 秒**；这 30 秒内回到页面即可自动重连回原座位（带令牌认领） |
| 超过 30 秒仍未回 | 该座位由 **AI 接管**继续出牌，名字前显示 🤖，游戏不卡住 |
| 已被 AI 接管后原主人回来 | 凭**同一浏览器里的令牌**可**认领回**原座位：恢复真人、名字去掉 🤖、座位号与手牌不变 |
| 重连宽限期 | 断线座位在 **60 秒**（`RECONNECT_GRACE_MS=60 秒`）内算「等待重连」；超过后房间可被正常回收，不再永久滞留。**准确口径（含实测数字）见紧随其后的「宽限口径（定稿）」** |
| **结算期 / 新局期掉线** | **不被 AI 接管**（`phase` 为 `settling` / `dealing` / `tribute` / `newRound` 时一律不接管）；等真正开打（`playing`）后才给仍断线的座位补挂 30 秒接管 |
| 半开连接（拔网线 / 休眠，连接没正常关） | 服务端每 **30 秒**心跳一次（WS 协议层 ping/pong，**客户端无需任何配合**）；无回应即回收该连接（控制台打「💀 心跳超时（30s 无 pong），回收半开连接」） |
| 观战者在场时房主离开 | **房间不会被解散**（解散判据 =「无在线真人 **且** 无在线观战者」） |

> **宽限口径（定稿 · 2026-10-16 实测）**：断线后 **30 秒 AI 接管照旧发生**（座位名字前出现 🤖、对局继续），**但房间仍保留到 60 秒宽限** —— 宽限以**本人断线时刻**（`disconnectTime`）起算、接管时不再被清空，**AI 接管不再截断它**。
>
> - **宽限内回来**：凭原令牌回连即可**取回原座位与手牌**（座位号不变、`isAI` 复位、名字去掉 🤖、手牌原样取回）。实测：断线 **35 秒**（已过 30 秒接管、仍在 60 秒宽限内）带令牌回连 → 收到 `{"type":"reconnected"}`，座位与手牌一并取回 → **PASS**（修复前同一步收到的是「房间不存在」）。
> - **超过宽限仍不回**：房间才被回收；回收由 **30 秒心跳扫描**触发，所以实际回收时刻落在 **60~120 秒**区间（实测 **82.8 秒**）—— 既守住了 60 秒宽限，也不会治出僵尸房。
> - **房内另有在线真人时行为不变**：房间本来就不会被回收，30 秒接管后原主人仍能凭令牌认领回原座位（实测 2 真人 + 2 AI 场景 **3/3 PASS**）。
> - **实测证据**（库外绝对路径）：`F:/HFF/_backup/掼蛋/20261016_155703/verify/s03c_grace_recheck_after.log`（35s 回连 PASS）、`verify/f1_35s_recheck_after.log`（35s 回连 PASS，改后新进程复现）、`verify/f1_recycle_watch_after.log`（回收 **82.8s**，期望 60~120s）、`verify/s03_grace_after.log`（同一脚本回收 86.7s）、`verify/s03e_multihuman_after.log`（多人房 3/3 PASS）

> 副作用（如实告知）：若有人在**新局进贡阶段**掉线又一直不回，而这一局正等他点「还贡」，本局会**卡在进贡阶段** —— 这是「结算 / 新局期不接管」的直接代价（后续会做超时自动代还贡）。

**▍ 房主管理门禁**

- 创建房间的人即**房主**（房间列表里可见 `hostId`）。以下三个操作**只有房主**能做：

| 操作 | 门禁 | 非房主 / 局面不符时的提示 |
| --- | --- | --- |
| **添加 AI**（`addAI`） | 房主 + 未开局 / 结算期（`waiting` / `settling`） | 「只有房主可以添加AI」/「当前局面（如 playing）不允许添加AI，请等本局结束」 |
| **测试模式**的结算按钮（`testWin`） | 房主 + 对局中（`playing`） | 「只有房主可以使用测试胜利功能」/「当前局面（如 waiting）不是对局中，无法模拟胜利」 |
| **新局**（`newRound`） | 房主 + 结算期（`settling`） | 「只有房主可以开始新一局」/「当前局面（如 playing）不是结算期，无法开始新一局」 |

- 这一批修复之前，**同房任意真人都能**点这些按钮（能一键结束别人正在打的一局、能中途重发牌打断对局）；现在会被上面这些可读提示拦下。
- 房主**离场**（已离开，或断线被 AI 接管后一直没回来）时，管理权**顺位给座位号最小的在线真人**，避免「房主一走，房里再没人能点新局」；房主本人回连后管理权自动回到房主。

**▍ 连接与消息限额**

服务端有一组硬上限，**超限一律回可读错误，不静默丢包**：

| 项目 | 上限 | 超限表现 |
| --- | --- | --- |
| 单个 WebSocket 帧 | **256 KB** | 由 ws 以 1009 关闭该连接（正常大广播实测约 11 KB，余量约 23 倍，不会误杀） |
| 每连接消息频率 | 约 **100 条/分钟**（起步可突发 60 条） | 回 `error` 帧：「消息发送过于频繁（上限 100 条/分钟），请稍后再试」（1 秒内只告警一次，避免错误本身放大流量） |
| 房间总数 | **200** | 建房回「服务器房间数已达上限（200），请稍后再试」 |
| 在线连接数 | **200** | 连接建立即回「服务器连接数已达上限（200），请稍后重试」并以 1013 关闭 |

> 这些是防呆 / 防滥用上限，正常人数（一桌 4 人 + 若干观战）**远远碰不到**。

**▍ 包间号规则**

- 包间号**全局唯一**：自定义号与自动号（服务器自增）**同进一个号池**，互不撞号 —— 不会再出现「先开自定义 5 号，再开自动号又分到 5 号」。
- 自动号会**跳过**所有已被占用的号（含自定义号与销毁后留下的空洞号）。
- 房间**无人**（无在线真人且无在线观战者）时会被回收，**包间号随即释放**，可直接重开同号。

**▍ 昵称与聊天：限长 + 一律纯文本（FIX-009）**

- **昵称最长 16 字**、**单条聊天最长 200 字**（服务端常量 `MAX_NAME_LEN = 16` / `MAX_CHAT_LEN = 200`）；超出部分在**服务端入口**就被截断 —— 页面里看到的就是截断后的样子（刻意行为，不是显示 bug）。
- 昵称与聊天里的换行、制表符会被折成**一个空格**，其它控制字符（含零宽字符、双向控制符那一类）会被删掉 —— 超长串打不爆广播帧，也不会把终端日志与页面排版弄乱。
- 聊天正文在**广播出线时**就做了 HTML 实体化（`&` `<` `>` `"` `'`），客户端再把实体还原成原文、以**纯文本节点**插入页面 —— 服务端与客户端**两层防护**，昵称与聊天在任何界面位置都**不会再被执行**（「昵称里写一段脚本标签就能让全房弹窗」这条路已堵死）。
- 副作用（如实告知）：直接抓 WebSocket 报文看到的是 `&lt;img …&gt;` 这种转义文本，**不是 bug**，是刻意把脚本挡在线路上。

**▍ 断线期间的操作会排队，提示不再静默（FIX-009）**

- **断线时点按钮不再静默丢**：没连上服务器时，操作会弹提示「⚠️ 尚未连接到服务器：该操作已排队，连接成功后自动发送」，并进入**最多 20 条**的待发队列（再超就丢最旧的一条）；重新连上后按原顺序自动补发（控制台打印「[发送] 已补发排队消息 N 条」）。
- **排队补发的边界（2026-10-16 实机实测，定稿）**：**对局中掉线时补发成立** —— 重新连上后按原顺序补发、服务端确实收到（最强的一条证据是同房观察者实收补发的聊天广播；9/9 断言 PASS）。**大厅（未开局）掉线时会话即失效**：大厅离场会立刻清掉座位与**会话令牌**（`removePlayer` + `revokeSessionToken`），客户端此时会**清空待发队列**，并给出可读提示「⚠️ 会话已失效（座位已释放）：刚才的操作没有执行，请重新加入房间」—— 此后点任何按钮都在**本地**被拦下，不再攒一堆永远发不出去的消息。**令牌吊销策略未改**：大厅掉线期间的动作**仍然会失败**（服务端照旧回 `NOT_BOUND`），客户端只是**不再谎报补发成功**，并如实回调「刚才发出的 N 条排队动作未被服务端接受」。端到端实测 **12/12 PASS**，证据 `F:/HFF/_backup/掼蛋/20261016_155703/verify/f2_lobby_queue_e2e_after_final.log`。
- **掉线 / 被 AI 接管现在全房可见**：有人掉线弹「⚠️ <昵称> 已断开连接，等待重连…」（消息类型 `playerDisconnected`），超时被 AI 接管弹「🤖 <昵称> 超时未重连，已由 AI 接管」（`playerReplacedByAI`）—— 这两条提示以前**是不存在的**（客户端缺这两个分支，消息被静默丢弃）。
- **坏帧 / 未知消息类型不再炸页面**：收到非法 JSON 或没见过的消息类型时，只在控制台留一行 `console.warn`，页面不抛未捕获异常、也不会中断后续消息处理。

**■ 常见问题**

**▍ Q: 如何让服务器自动重启？**

**A:** 两种模式都会自动重启，选一个即可：

- **自动重启模式（开发推荐）**：`npm run dev`，或双击 `启动服务器-自动重启.bat` —— 由 **nodemon** 监视，改 `guandan-server.js` 后 1 秒内自动重启（按 `rs` + 回车还能手动触发）。
- **普通模式**：`npm start`，或双击 `启动服务器-普通模式.bat` —— 服务器**内置 `fs.watch` 自重启**，改 `guandan-server.js` / `guandan-lan.html` 后触发**同进程原地重启**：**进程不退出、PID 不变**，端口 8081 重新监听，房间清空（与 nodemon 重启同语义），**不需要手动关掉再开**。

> ⚠️ 两种方式都会**作废会话令牌、清空所有房间** → 在场所有人需 **F5 一次**（见「会话、身份与限额 → 会话令牌」）。

**▍ Q: 无法连接到服务器**

**A: 检查以下项目:**
1. 确认服务器已启动 (`node guandan-server.js` 正在运行)
2. 确认IP地址和端口正确
3. 检查防火墙设置,允许8081端口（企业统一管控(GPO)的电脑 `LocalFirewallRules N/A`，自己加不了本地放行规则 → 手机/别的电脑可能连不上，需找 IT 放行）
4. 确认客户端和服务器在同一局域网

**▍ Q: 端口8081被占用**

**A: 修改 `guandan-server.js` 第 9 行的端口号:**
```javascript
const PORT = 8082; // 改为其他端口
```

**▍ Q: 游戏卡住不动**

**A:** v2.1.3 起客户端会**自动重连**（断线按 1→2→4→8→10 秒退避，成功后自动回到原房间，并带上会话令牌认领原座位），一般不需要手动处理。仍然卡住时才依次尝试：
1. 按 F5 刷新浏览器页面（顺手按 F12 看一眼控制台有没有红色报错）
2. 检查网络连接状态
3. 看页面右上角是不是「已连接」；若弹出「请按 F5 刷新页面后重新加入房间」的红条，说明服务器重启过、会话令牌已作废 —— **F5 一次**即可
4. 最后才重启服务器（注意：重启会清空**所有房间**，且会话令牌全部作废 → 在场所有人需 F5 一次）

**▍ Q: 服务器日志写在哪？目录里的 `server.log` 是什么？**

**A:** 服务器**只往控制台（那个黑窗口 / 命令行窗口）打印，不写任何文件日志**。目录里的 `server.log`（约 125KB）是 **2026 年 4 月遗留的旧文件**，跟现在的服务器代码没关系，可以直接删掉。排查问题一律看控制台输出。

**▍ Q: 玩家中途离开怎么办？**

**A:** 从 v1.9.0 起，游戏进行中如果有玩家断开连接（关闭浏览器、网络断开等），系统会在 **30 秒后**自动将该玩家替换为 AI 继续出牌（这 30 秒里他还能靠自动重连回到原座位），游戏不会卡住；该玩家名字前会显示"🤖"标识。原主人回来后可凭**同一浏览器里的会话令牌认领回**该座位（恢复真人、名字去掉 🤖、座位号与手牌不变）。

v2.1.3 起这条链路更精细（详见上文「会话、身份与限额」）：
- **结算期 / 新局期（发牌、进贡、新局）掉线不会被 AI 接管**，等真正开打后才补挂接管；
- 断线座位保留 **60 秒**（`RECONNECT_GRACE_MS=60 秒`）算「等待重连」，超期后房间可被回收，不再永久滞留（**含「房里再无在线真人」的情形 —— 30 秒 AI 接管不再截断宽限；准确口径与实测数字见「会话、身份与限额 → 断线、重连与 AI 接管」的「宽限口径（定稿）」**）；
- **有观战者在线时房间不会被解散**（解散只看「无在线真人 **且** 无在线观战者」）；
- 半开连接（拔网线 / 休眠）由服务端 **30 秒心跳**回收。

- 顺子、连对等需要连续的牌
- 炸弹需要4张以上相同的牌

**A:**

- 任意玩家点击"下一局"按钮即可开始

**▍ Q: 点「⚡快速 / 🎮正常」没反应，建不了房间？（v2.1.3 已修）**

**A: 先看这三处，能定位 90% 的情况:**
1. **页面右上角是「已连接」还是「未连接」** —— 未连接就什么都开不了（服务器没起 / 连不上）。
2. **地址栏是不是 `file:///`** —— 直接双击 HTML 文件打开是连不上服务器的（页面顶部现在会弹红色横条提示），必须用 `http://localhost:8081` 或启动服务器时提示的局域网地址。
3. **服务器控制台**（那个黑窗口）里有没有「房间创建」—— 只有「收到消息: type=createRoom」而没有「房间创建」，基本就是包间号被占了（见下一条）。

> 历史坑：v2.1.3 之前，「开房」卡片上的按钮**只在连上服务器后才绑事件**，所以连不上时那张卡是块死图，点了完全没反应、页面也不报错。

**▍ Q: 提示「包间X已存在，请更换号码」？**

**A:** 说明这个包间号还有房间占着（**哪怕房主已经关掉页面**）。两种情况：
- **无人在线（僵尸房）**：v2.1.3 起服务器会自动回收这个包间号，直接重开就行。回收判据是「**无在线真人 且 无在线观战者**」—— 只要还有观战者在线，房间**不会**被解散（旧实现会因为「4 人全是 AI」把有观战者的房间也悄悄解散，已修）。
- **真人在玩**：提示里会写明是谁在玩、是「在房间里」还是「对局中」。换一个包间号，或让对方离开 / 关掉页面（离线 30 秒由 AI 接管；房间无人、或断线满 60 秒宽限后被回收，包间号随即释放；**该 60 秒宽限的准确口径与实测数字见「会话、身份与限额 → 断线、重连与 AI 接管」的「宽限口径（定稿）」**）。

号码规则（v2.1.3）：包间号**全局唯一**，自定义号与自动号**同进一个号池、互不撞号**；自动号会跳过所有已占用的号；房间回收时号码**立即释放**，可直接重开同号。

**▍ Q: 服务器重启（改代码）以后要不要手动刷新页面？**

**A: 需要，按一次 F5。** v2.1.3 起客户端仍会自动重连（1→2→4→8→10 秒退避），但重连**必须带会话令牌**，而**令牌是内存态** —— 服务器每次重启（含改代码触发的 nodemon 自重启）令牌**全部作废**、所有房间被清空。所以重启后：

1. 页面会弹可读红条「⚠️ 会话令牌已失效：**请按 F5 刷新页面后重新加入房间**（服务器重启会让旧令牌作废）。」（服务端文案：「重连凭证无效或已过期：请按 F5 刷新页面后重新加入房间」）
2. **按一次 F5**，页面重新握手拿到新令牌，再重新加入房间即可。

> 说明：v2.1.3 早期写的「重连成功会自动回到原房间、重启后不用 F5」**已被令牌化取代** —— 现在**每次服务器重启都需要 F5 一次**。

**■ 开发说明**

**▍ 自动重启模式（推荐）**

使用自动重启模式开发，修改代码后服务器会自动重启：

```bash
npm run dev
```

或双击 `启动服务器-自动重启.bat`

**监听的文件:**
- `guandan-server.js` - 服务器代码
- `guandan-lan.html` - H5客户端

**特性:**
- 文件修改后 1 秒自动重启
- 无需手动终止和重启服务器
- 按 `rs` + Enter 可手动触发重启（**这是 nodemon 专属**，普通模式没有）

**▍ 手动重启（普通模式）**

普通模式的**内置自重启就是「同进程原地重启」**（v2.1.3 起）：`node guandan-server.js` 在非 nodemon 环境下会注册内置 `fs.watch`，监视 `guandan-server.js` 与 `guandan-lan.html`，检测到改动即**原地重启** —— 顺序固定为「关掉所有 WebSocket 连接（1001）→ 清空房间与会话 → 关掉旧 http server → 换新的 WebSocket 服务实例并**重新监听 8081** → 重挂心跳与文件监听」，**全程不退出进程（PID 不变）**；控制台会依次打印「🔄 检测到 … 变化，正在重启服务器…」「♻️ 内置自重启（同进程原地重启，PID x 不变）」「♻️ 原地重启清理：销毁房间 N 个…」「✅ 原地重启完成：PID x 不变，端口 8081 已重新监听，房间已清空」与「👀 已挂载文件监听」。**房间随之清空，语义与 nodemon 重启一致**。v2.1.3 起，nodemon 模式下这个内置自重启会自动**让位**给 nodemon，避免两个重启器抢 8081 端口；只有原地重启自身失败（5 秒内未完成 / 重新监听报错）才打印「❌ 原地重启失败…」并退出本进程（`exit(1)`，交由外部启动器拉起）。

> ⚠️ **尚未经真机验证**（代码已落地；真机验证见待办）：上面这条「同进程原地重启」目前只有代码层断言（13 步序列、PID 不变、房间清空）与离线桩验证，**还没在真机上实跑过一次** —— 该验收由另一条 e2e 环节负责（要点见文末「待同步」第 1 条）。

> ⚠️ 无论用哪种方式重启，**会话令牌都会作废、所有房间都会清空** → 在场所有人需 **F5 一次**（见「会话、身份与限额 → 会话令牌」）。

需要手动重启时（例如端口被占、想强制清空所有房间）：

1. 按 `Ctrl+C` 终止服务器
2. 重新运行 `npm start`

或强制终止进程:
```bash
＃ Windows
netstat -ano | findstr :8081
taskkill /PID <PID> /F

＃ PowerShell
Stop-Process -Name node -Force
```
